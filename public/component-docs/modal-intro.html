Components · Overlays · Modal

One dialog per decision. The page waits.

Modal is the blocking dialog for a single focused task — import data, add a profile — that keeps the page behind it inert until confirmed or dismissed. Use it when the user must decide before continuing; reach for card or list-row when content is meant to be read, not resolved.

  • 01

    Content composes fields, never dialogs. The body may hold field.md grids and tab.md tabs at spacing.md gaps inside the spacing.xl shell — but never a second modal. Sizes run compact → medium → large → wide; the library index strip is not a dialog.

    Reject: a confirm dialog opening a second dialog — stacked decisions strand focus.

  • 02

    Footer is right-aligned, cancel before confirm. Neutral secondary plus a single color.brand.navy primary at spacing.md gap above a color.border.default divider. The primary is the only navy element in the dialog.

    Reject: two navy buttons, or confirm-left-of-cancel — muscle memory misfires.

  • 03

    Focus is trapped, Esc always exits. role="dialog" with aria-modal="true", labelled by the text.2xl title; focus trapped inside with color.brand.sky rings, restored to the trigger on close. Background stays inert; errors report inline in color.semantic.danger with the dialog open.

    Reject: a dialog that closes on submit-failure and eats the error with it.
