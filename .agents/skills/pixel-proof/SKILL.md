# Pixel Proof

Use when shipping UI work that must be verified visually — component showcases, galleries, style guides, or any batch where the user judges pixels, not code.

## When to Use
- Finishing a component/CSS batch and needing to prove it renders (design systems, style guides, galleries).
- The user says pixels look unchanged, asks for screenshots, or judges work visually.
- Any showcase page with fetched partials, tabbed panels, or framework-served assets that needs capture + verification.

## Rule
A UI batch is done when its showcase renders every variant screenshot-clean — never when the code merely reads correct. Refactored CSS that keeps old showcase markup renders identical pixels and correctly reads as no change.

## Workflow

### 1. Showcase every variant
- One panel per component group, one row per variant/size/state, each panel ending in a caption (anatomy + tokens + one rule) plus a link to its spec contract.
- Keep showcase shells thin: variant markup lives in fetched partials (e.g. the Vite `public/` dir loaded via `fetch`), never inline in the index page — this also holds file line budgets.
- Use only classes confirmed to exist in the stylesheets (grep before writing markup); never reference deprecated icon systems or removed partials.
- Contain each specimen in its own framed stage and let the **stage own its layers' geometry**: absolute layers get explicit `top/right/left` (and `position`) in the stage scope, so a layer can never fall back to its static position — centred in a centring container — when a base rule is missing or stale. Stage anatomy, lane re-centring and open-state deep links: `references/showcase-stages.md`.

### 2. Keep fetched panels alive
- Content loaded via `fetch` misses directly-bound JS listeners: bind all showcase interactivity (toggles, sorting, accordions, tabs, deep-links) with delegated `document`-level listeners.
- Deep-link panels (`#actions`) and scroll the active panel into view on navigation, so each panel is capturable and shareable by URL.
- Deep-link an open state too (`?open=<layer-id>` opens that specimen's layer once its panel lands), so a layer can be captured without a click — indispensable when the browser in question cannot be scripted. Never fire that synthetic `.click()` before deferred module listeners attach: retry idempotently on `DOMContentLoaded` plus a later tick, guarded by the layer's own `hidden`, because a click with no listener yet is a silent no-op that looks exactly like a broken feature.

### 3. Capture against the real server
- Screenshot every panel headless against the live server that owns the routing (recipe: `references/headless-shots.md`) at full scroll height, then inspect each shot for the expected rows before presenting — a viewport crop that ends mid-section proves nothing about the content below it.
- Capture through `scripts/capture-page.mjs` (CDP driver: launch Chrome with `--remote-debugging-port`, set device metrics, navigate, wait in real time, `Page.captureScreenshot`). Chrome's one-shot `--headless --screenshot` flag can hang indefinitely on a live Vite page — the HMR socket and render loop keep it 'busy' so the process never exits and no file is written (`--virtual-time-budget` does not cap it); when a one-shot capture times out, switch to the CDP driver, never retry the flag.
- Confirm 404s and asset paths against that same server before deleting any reference — temp static servers do not replicate framework mappings (e.g. Vite `public/` → root), and acting on their errors deletes live code.
- WebGL pages render black under headless without software GL: a capture showing only the page background plus a `THREE.WebGLRenderer: Error creating WebGL context` overlay means the GPU path is missing, not that the site is broken — relaunch with software rendering (`--use-angle=swiftshader --enable-unsafe-swiftshader`) and capture again before reporting any verdict on the scene. Even with software GL, a black masked canvas is not proof of an empty scene: SwiftShader runs ~1 frame/2 s at 1280x800, so every frame-driven diagnostic is starved — check liveness first with an RAF heartbeat (count `requestAnimationFrame` ticks over 2 s; near-zero means starved, not empty), drop to 640x400, and budget 20-60 s per capture for tiles/DEM to land. And isolate compositing from scene before debugging the renderer: strip `mask-image`/`clip-path`/opacity CSS on the canvas in-eval and re-capture — if content returns, the fault is the mask/lens state, not the scene — toggling mask-only, clip-only, and lens-state one variable at a time.
- When a reference page renders black headless (its WebGL needs a real GPU), read its shipped bundle instead of its pixels: `curl` the JS chunks and grep for palette literals, HUD copy, and renderer flags — the exact hexes and wording carry the language even when the scene won't render.
- Never disturb the user's own dev server: read from it freely, but run temp servers on other ports and kill nothing.
- Drive the control the source wires, not the first match: pages carry several same-type inputs (a 0..8 auxiliary range beside the 0..100 mix slider), so read the handler first — which min/max the listener divides by — and assert the in-page effect (mask style, opacity, HUD text) immediately after setting, before capturing. A capture of the wrong control's state reports success on nothing and reads as a phantom regression of a fix that actually landed.
- When a capture shows a blank or foreign page, prove server identity before debugging the app: `curl` the root and check `<title>`, and match the listener (`lsof -i :PORT` + `ps`) to the project — the port may belong to a sibling project's server, and its white empty page reads exactly like your app failing to render.
- Verify in the engine the user actually browses with. When their browser is Safari (the macOS default), a Chrome-only pass is not proof of what they will see — reproduce layout and interaction in **WebKit** (`npm i playwright && npx playwright install webkit`, then run `scripts/webkit-probe.mjs`) and report the same measurements from both engines before claiming a fix. Confirm which browser they are on first: `browser_exec(local=True)` refuses with 'default browser is not a supported Chromium browser' when it is not Chromium, and a read-only `osascript -e 'tell application "Safari" to get URL of every tab of every window'` lists the exact URLs they have open without needing any permission toggle (`do JavaScript` needs Allow JavaScript from Apple Events, System Events clicks need Accessibility).
- Measure geometry, don't estimate it: vision passes misread coordinates (two reads of one shot can disagree on whether a layer is docked or floating), so back every 'docked / centred / clipped' claim with `getBoundingClientRect()` evals or pixel-run measurement of the capture (`references/headless-shots.md`). State the expected number inside the question itself ('focus centre should read ~41%') and ask for a measurement against it — an open-ended 'is it centred' verdict reads a correct intentional offset as a bug even when its own numbers match. Presence is the same trap in both directions: a vision pass reports a thin 1–2px stroke or line as missing while it renders, and equally reports a line as present while it is absent (a nearby edge or junction implies it) — answer "is X there / how many" with a scanline run-count on the capture (count runs per row/column through the feature), and treat any vision yes/no about a hairline as a hypothesis to confirm numerically. Full-frame regions misread the same way: an empty background area reads as a letterbox bar, vignette fault, or missing fill — sample the region's actual pixel values before treating it as a bug. Ask the vision pass about a crop, not the whole page: a full-height capture (1800×2700-ish) can stall the call, so PIL-crop the region under test (≤~1400px wide strips) and keep the full shot only as the artifact you attach. To measure a hidden panel's docked geometry without driving app state, strip its hidden class in-eval and read `getBoundingClientRect()` — position rules apply regardless of visibility, so the numbers prove docking even when the panel is normally closed. When the user's own screenshot is the evidence, measure it the same way before touching code.
- Read on-screen copy from the DOM, not from the pixels: have the harness dump `innerText` (or eval `textContent`) and assert exact strings there — small mono type misreads and re-wraps under vision OCR, so the text dump is the verdict and the screenshot is the artifact. Same for open/closed widget states: click headless, assert the state's DOM text, then capture.
- Frame parity captures to the reference's own dimensions: a capture whose size/aspect doesn't match the target image makes a vision pass compare framings, not content — a default-sized clip reading 'cube too small / shadow huge' against a 1600×1200 hero render is a framing artifact, not a parity finding. Set the capture size to the reference's pixel dimensions before judging parity, and when the user asks for independent vision agents on parity work, give each one the reference and the capture side by side.
- Prove an effect with an on/off pixel-diff, not eyeballing: capture once, inject a disabling style, capture again, and diff (recipe: `references/headless-shots.md`). Set effect thresholds against measured color luminance, not gut feel: pure red's luminance is ~0.3, so a bloom cutoff of 0.55 silently blooms everything except the critical-red alert it exists for — sample the target color's luminance first. Never trust the assumed winner: compute which palette entries actually clear the threshold (a critical-red body can ride UNDER it while lamp dots and white pins do the visible work) and lock the true relationships in a unit test — threshold, carrier luminances, and hue separations — so a later threshold bump cannot silently kill the effect the test was written to protect. Blur over a flat background diffs to zero even when working, so position textured content under the effect first — and a max diff in the noise range (≤3/255) means the layer renders nothing, so debug the layer, not the strength.
- On an animated page the render loop owns material state: an injected diagnostic that only sets properties the loop repaints (a shader uniform colour, an object's opacity/scale) is reverted on the next frame, so the capture keeps reading 'invisible' no matter how loud the forced value. Prove presence with state the loop does not own — hide-and-diff renders (`visible=false` toggles), strip the texture (`map=null`) at opacity 1, scene-graph enumeration + raycast — and only then call it missing. On nested-rig pages enumerate the graph first: a handle that isolates clean while pixels persist is usually aimed at the outer staging layer, not the mesh owner — confirm the handle addresses the mesh before concluding anything about its material.
- Separate 'renders' from 'reads': a layer can draw every frame yet composite to nothing — a glow plane stacked under a semi-opaque shadow plane (fix: explicit y-order + `renderOrder`), a pale tint multiplied by a soft-alpha texture falling sub-threshold (fix: a stronger-core texture, white-lerp ≤ 0.2), 1px canvas strokes at high texture `repeat` fading out in mip filtering (fix: stroke ~1.5px + `texture.anisotropy = 8`). Isolate layers (hide the neighbours / strip the map) before debugging strength. When the scene graph is reachable, enumerate before theorizing: expose the scene on the dev harness (a `window.__app` handle plus `debug.scene`) and in-eval list object types, material uniforms (opacity, dashOffset sampled twice for animation), and geometry bounds — live objects with animating uniforms and sane bounds mean renders-but-invisible (chase depth/composite next), while an empty traversal means missing (chase construction).
- Never nest `backdrop-filter`: a filter on the parent box starves the blur layers inside it (child/pseudo `backdrop-filter` computes against nothing) — keep tint on the box and put ALL blur in un-nested layers, with foreground text isolated above them on its own `z-index`.
- When their render contradicts the files, triage staleness first — dead dev server, cached `fetch` partial — before debugging CSS; the tell is text in their shot that no longer exists on disk. And symmetrically, your uncommitted fixes don't exist on THEIR server — when their evidence predates your commit, announce pull + hard reload before they read the old pixels as your regression. Also diff the capture's own timestamp (screenshot filenames embed it, e.g. `…_at_7.02.26_PM`) against the fix's landing time (file mtime / commit time): a shot taken before the fix cannot show it, so 'still see it' backed by a pre-fix capture is a stale surface, not a regression. Then prove the served bytes instead of asserting them — `curl` the dev server's module URLs and grep for a distinctive literal from the fix (an exact coordinate/string that exists only post-fix); served text is the truth. A same-URL navigation that differs only in the hash/fragment re-runs nothing, so a page that fetches its partials once per load keeps pre-edit text through any number of "reloads" — force a real load with a cache-busting query (`?cb=2#panel`) before concluding an edit didn't land. Vite HMR is a special stale: a new build stamp in their bar proves only the stamped module re-executed — the fixed module may never have re-run in their long-lived tab, so matching stamp plus persisting bug means full hard reload, not another code change.
- Never read app state through a bare dynamic import in a probe eval: Vite dev serves the page graph with an HMR `?t=` query, so `import('/src/x.js')` instantiates a forked module copy with isolated state and the diagnostic reads idle defaults while the app runs on the other instance (prove via `performance` resource names showing the `?t=` URL). Read live state through window-exposed handles (`window.__app`, status accessors) instead.
- In multi-lane loops an audit capture goes stale the moment a fix lane lands — check fix commit times against the capture time and re-verify each ranked defect on fresh pixels before dispatching a fix lane from it, or lanes re-fix already-fixed defects and report phantom regressions.
- Async base layers (satellite tiles, CDN maps) need visible loading and failure states: an opaque base floor (never transparent), a LOADING indicator until first tiles, and a watchdog that swaps in an OFFLINE tag. A silently empty layer reads as a black hole and debugs as a render bug. Vet the source before wiring it: `curl` with `Origin` + `Range` headers must show usable CORS — a bucket that 403s preflight can never load in-browser no matter how fast plain ranges feel (vetted source table: `references/browser-raster-sources.md`).
- New fixed-position controls must clear existing HUD hit-boxes: capture the bar against the full HUD and assert no overlap with system clusters before calling it placed — a bar under a button row is unclickable, not merely ugly.
- When the user supplies the target as media (a screen recording/screenshot of the object), judge against the same frames: `ffmpeg -i <rec.mov> -vf "fps=1/1.4,scale=520:-1,tile=4x3" sheet.png` gives one vision pass over the whole arc, then extract full-res singles for detail — and close the top gaps in the same run; they judge on the recording, not on a report. Resolve attachment paths programmatically — macOS recording names carry a narrow no-break space (U+202F) that breaks literal shell quoting, so list the directory instead of typing the name. When the defect is a transient interaction state (mid-drag, mid-fade), sample across time at fps=1 and vision each frame instead of only the contact sheet — the single proving frame lives between keyframes, and endpoint frames alone report a snapping control as working.

### 4. Present shots, not descriptions
- Attach the screenshots themselves; a prose summary of what changed is not proof.
- When they ask for the server link or "where is it rendered": give the URL AND open it in the desktop preview pane (`desktop_preview`) — a screenshot answers "what changed", the live pane answers "where is it", and they judge in the app they are already in.
- When the user asks for 'a screenshot of what changed', they mean the rendered product pixels — capture the page itself; a meta/evidence graphic about the agent's process (a poster explaining what happened) reads as 'not what I asked for' and gets rejected.
- Report compactly: what changed, what is still unverified or broken, what remains.

### 5. Measure motion, don't just screenshot it
- A shot proves a frame; only frame stats prove smoothness. After the captures, run the headless scroll probe (`scripts/scroll-probe.mjs`, full recipe in `references/scroll-probe.md`): scripted slow scroll + flicks while sampling rAF timestamps, then assert p50/p95 gaps, zero `longtask` entries, no `NaN` in animated transforms, zero pageerrors, and identical state snapshots cold vs reload.
- Headless stats prove the absence of jank sources, not perceived smoothness — still verify on the engine the user browses with (§3) before claiming a fix.
- Sample animated state per frame, not just screenshots: record rig values (rotation, positions, colors) each `requestAnimationFrame` via CDP `Runtime.evaluate` and assert lock-step numerically — a still cannot show a one-frame lag, and a color that swaps only at a morph's end reads as motion 'delay' while every transform stays glued.
- Sample animation states deterministically when the harness is single-shot: in the gem-shot CDP harness `--eval` runs after `--wait` and before the screenshot, so jump the rig clock (`r.clock=30; r.t=30`) to capture settled or pushed states on demand — prove an animated behaviour with ≥3 clock states (e.g. hue travel at 0/22/44), never one still. The same applies to hidden surfaces: clip the mounted canvas of a non-default tab (`--clip "canvas[data-cube]"`) only after its panel actually shows it.
- For wall-time-driven behaviour (tweens, fades, chains running on `performance.now`, unreachable by clock jump), act, sleep, and read INSIDE one async evaluate — `toggle(); await sleep(N); return JSON.stringify(read())` — instead of sleeping in the driver between two evals. Driver-side timing races the software renderer's frame cadence and the sample lands anywhere; the in-eval sleep resolves on the settled state. Keep the sleep inside the harness per-message timeout.
- Compare repeated captures with a masked tolerance, never byte equality: same-clock re-renders differ by rAF dt-settle noise, and long software-rendered passes flake single blank frames — a lone blank is a re-run signal, not a verdict, and a byte-identical gate proves the clock froze, not that the pixels are right.
- Keep CDP evals total: put `JSON.stringify` INSIDE an async eval (stringifying the returned promise yields `{}` and the real result is dropped), and never await a promise that can pend forever — `AudioContext.resume()` without a trusted user gesture never settles and the harness times out the whole run. In untrusted-gesture contexts assert only settled state (status strings, cue logs, engine state).
- Never read post-interaction verdicts from `--dump-dom`: it serializes the zero-frame DOM (no `requestAnimationFrame` ticks run), so scripted clicks and tweened cameras always report their start state as FAIL. Drive scripted checks by frame-counted `requestAnimationFrame` sequencing (wall-time timers fire long before software-GL frames render) and read the verdict out of a screenshot-mode capture, where frames actually advance.
- Read a scripted FAIL as harness evidence first, never as an app verdict: re-derive what the gate actually measured — which frame it sampled, what the tween clock read, whether synthetic input threw — before filing it as an app bug. Retuned durations invalidate old gates (a check firing mid-flight reports the start state as FAIL), so update the harness to the new timing or verify by eye. Filter `setPointerCapture` errors out of harness collectors: synthetic `PointerEvent`s dispatched with no active pointer always throw it, and it masquerades as an app regression in the error list.
- Assert the settled marker, never the click point: a scripted click-to-centre gate must project the asset's marker anchor (fault chainage / position) after the fly duration plus margin and require NDC ≈ 0 — asserting the clicked dirt passes while the object sits in a corner.

### 6. Score every run, revert regressions
- Score each capture 1–10 against the reference with the single weakest thing named; fix exactly that thing next run. One variable per run keeps the trajectory readable.
- When a score drops, revert the speculative change first instead of stacking more fixes on top — a regression reverted same-run is what lets the next run beat the previous best.
- When the user supplies references (images, URLs), distill each to its recipe in module terms — what carries the look, which file owns it — and queue the recipes so the language compounds instead of restarting each run.
