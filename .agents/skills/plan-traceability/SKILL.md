# Plan Traceability — Bidirectional Plan ↔ Execution Link

Class-level workflow for repos where `.hermes/plans/*.md` is the source of truth and `src/ds/pages-changelog.js` (or equivalent) must show every plan and every execution that touched tracked paths. Guarantees future scopes auto-appear with zero manual bookkeeping.

## When to use

- Repo has `src/ds/pages-changelog.js` / `.hermes/plans/` and you need "all DS changes tracked" or "each plan bidirectionally linked"
- User asks to guarantee future scopes from a session continuation (e.g. `20260909_145218_9888b1`)
- Changelog hard-codes 2–3 plan imports, shows drift (`Phase 0 → 01`), or `changelog-manifest.json` is missing at build time

## Core guarantee

- **Plan → commits:** Vite eager glob makes every future MD with `## Phase` appear in Miller column 1 without touching the renderer.
- **Commits → plan:** EVERY commit cites `[plan:<file>#<anchor>]` — no path exceptions (skill snapshots, gitignore, docs-only, merch commits all carry trailers). A commit with no owning task takes the closest plan + `null` anchor via `plan-retro.json`, never left unlinked. Pre-commit: name the plan+anchor before writing the message; post-commit: run the tracker and triage any unlinked immediately (retro entry, not history rewrite).
- Anchor `continuation` (session ID) persists in both `.hermes/continuation.json` and `manifest.continuation` so any later session can `session_search` the same root.

## Procedure

### 0. Preflight — SOP auto-gate (never ask)

Before touching code for any phased plan, run the gates and fix before implementing — this SOP is law in `AGENTS.md §5` / `.cursorrules §5` so the user never re-prompts:

```bash
node scripts/plan-names.mjs   # must be ✓ — 0 missing names
node scripts/ds-track.mjs     # must be N/N tagged, 0 wip (1 wip is expected only for a brand-new plan before its first commit)
```
- If `plan:names` reports missing entries, add `src/ds/changelog-names.json` `{title ≤76ch, purpose}` for each flagged `*.md` before any code change — titles are LLM-curated, purpose is 2–4 words; derive the title from the plan's **Goal** outcome (what the user can now see/do), not from technique inventory or file list — e.g. `FX + Motion legible — what each token changes, one screen` states outcome where `FX as tabbed tables — cards, elevation + motion` only lists technique and reads as duplicate; keep JSON as one object (order chronological), verify length ≤76ch. When authoring the plan under plan-mode constraints (plan markdown only, no project edits), do not make that JSON edit yourself — write it as Task 1 of Phase 1 so the implementer lands it before any other work, since plan-mode forbids touching project files.
- If `ds-track` reports `X/Y tagged` with X<Y, the preamble lacks `**Tags:**` or `**Tech Stack:**` — every phased plan header MUST have `**Goal:**`, `**Architecture:**`, `**Tech Stack:**`, `**Tags:** a, b` (closed set: Design System, Component, Function, Motion, Layout, Tooling). Add the missing line immediately above the first `---`.
- After fixing, re-run both gates and commit the fix with the active plan's `[plan:<file>#phase-N]` trailer (or the flagged plan's own trailer for retro fixes) — never start the feature on a failing gate.
- When the user says "make it part of project rule so I don't have to ask", persist the SOP in the repo's `AGENTS.md` / `.cursorrules` (repo is the project's memory), not in chat memory — see §10.

### 1. Establish tracker

Create `scripts/ds-track.mjs` (≤40 lines) that:
- Reads `.hermes/plans/*.md` filenames sorted.
- Runs `git log --format='%H|%h|%ad|%s' --date=short -- <DS paths>` (`src/ds`, `src/styles/tokens.css` + `tokens-dark.css` + `tokens-fx.css` (the whole `tokens*.css` family), `DESIGN.md`/`design.md`) — single-quote the format string or the shell expands `%H`.
- Parses trailer `TAG = /\[plan:([^\]#\s]+)(?:#([^\]]+))?\]/` into `{sha,full,date,subject,plan,anchor}`.
- Collects wip via `git status --short -- <DS paths>`, excluding the manifest file itself — the tracker always rewrites it at generation, so listing it as wip is self-noise that keeps a clean tree from ever reading "All tracked".
- Writes `src/ds/changelog-manifest.json` as `{generated, continuation, plans, commits, wip}`; if log is empty or git unavailable, still write a placeholder so the static `import manifest` never crashes.
- Shallow-clone guard: CI hosts truncate `git log` at build time (Vercel clones with `--depth=10`), so the tracker must MERGE fresh commits over the previously written manifest (dedupe by sha, fresh entries first) instead of overwriting — otherwise deploys show only the last few days while localhost shows full history. Log a line when `git rev-parse --is-shallow-repository` reports true. (`VERCEL_DEEP_CLONE=true` is optional belt-and-braces, never the only fix.)
- Portfolio retro injection (heat graph + badges): `git log -- <DS paths>` never sees portfolio-only commits, so their shas live only in `.hermes/plan-links.json` and would stay invisible to the calendar heatmap and `hits()` badges even after retro-mapping. After merging `prev` and applying retro anchors to existing `commits`, iterate `Object.keys(retro)` — for any short sha not already in `commits`, run `git show -s --format='%H|%h|%ad|%cI|%s' --date=short <sha>` and push `{sha, full, date, time: iso.slice(11,16), subject: subject.replace(TAG,''), plan: retro[sha].plan, anchor: retro[sha].anchor}`. Then `commits.sort((a,b)=> (b.date+b.time).localeCompare(a.date+a.time))` so the manifest itself carries portfolio history and the graph `dc[date]` counts portfolio days.
- **Docs-only variant (crm_proj — no `src/`, no `package.json` before Phase 6):** DS paths are `DESIGN.md`, `design-system`, `tokens`, `src` (future), `prototype`, `preview.html`, `scripts`, `tests` — not `src/ds`/`src/styles/tokens.css`; manifest lives at `design-system/changelog-manifest.json` (not `src/ds/`), wip excludes both the manifest and `*.md` plan files (plan edits never count as wip), and `fileURLToPath` + `dirname` + `join` is required for repo root (spaces in `Portfolio Redo` break `new URL('..', import.meta.url).pathname` with `%20`). `lint:tokens` paint check must be prose-aware (`:\s*#[` / `style="[^"]*#[`) only) and contrast pairs must mirror `DESIGN.md` pill atoms (ink vs white).
- **Lightweight variant (repo has `.hermes/plans/` but no changelog renderer, no names registry, no gates):** do NOT port the full pipeline — ship a minimal `scripts/plan-track.mjs` (~60 lines: plans glob + `git log -- <tracked paths>` + trailer parse + `{generated, plans, commits, wip}` manifest + shallow-merge) with an `npm run plan:track` script and a `build` hook. Tracked paths are the repo's own surface dirs (e.g. `src/ds design-system src/<feature> docs gallery.html`). The manifest is the whole UI until a renderer exists — `plan:track` output (`N plans · M commits (K linked) · W wip`) is the triage surface. Retro links live in `src/ds/plan-retro.json` (array of `{sha, plan, anchor, note}`), not `.hermes/plan-links.json` (map form — full pipeline only); the lightweight tracker applies retro entries only to trailer-less commits, so it can never re-point a commit whose subject already carries a trailer — a mis-trailered subject is permanent short of history rewrite, which is forbidden. Grow into the full pipeline only when a changelog page actually needs it.

### 2. Establish link layer

Create `src/ds/changelog-links.js` (≤25 lines):
```js
import manifest from './changelog-manifest.json';
export const commits = manifest.commits || [];
export const wip = manifest.wip || [];
export const continuation = manifest.continuation || '<id>';
const badge = (c) => `<a href="${GH}${c.full}">${c.sha}</a> ${esc(c.subject)} <small>${c.date}${c.time ? ' ' + c.time : ''}</small>`; // date + time (time from %cI slice, retro-injected too) — calendar tooltip and badges must show HH:MM, not just YYYY-MM-DD

export const hits = (file, text, first) => commits.filter(c => c.plan===file && (c.anchor ? text.includes(c.anchor) : first));
export const badges = (list) => list.length ? `<p class="ds-commits">${list.map(badge).join('<br>')}</p>` : '';
export const unlinked = (texts) => { /* commits with no/mismatched plan */ };
```
Anchor-less commits attach to first phase; anchored ones attach to first phase whose body contains the anchor.

Rewrite `src/ds/pages-changelog.js` (the module has outgrown its original 100-line budget with tags, timeline, and drawer state — the hard line cap applies to stylesheets via lint, not to this module):

Derive label from filename + first `#` heading, extract `**Goal:**` for the cursor-follow tooltip, split each MD on `^## ` and keep `^Phase ` entries (normalize `### Task` blocks to `- [ ]` if needed). Iteration card layout: one flex row per card (`num + title + tags pushed right via margin-left:auto`, title ellipsizes) with the meta line (`date · time · N phases · d/d`) as the `<small>` — phases stat sits on the date line, tags never wrap to their own line. Compute per-phase `state()` with case-insensitive `/- \[x\]/gi` and fallback to `^### ` heading count for IA-style plans. Aggregate `iterState()` for the plan column. Derive `isDone(s)` from the `d/t` string and apply accent only when done — Miller `.ds-num` defaults to `var(--color-ink-muted)` and gains `.is-done{color:var(--color-accent)}` only when `isDone` is true for that Iteration (`iterState(p.sprints)`) or Phase (`state(s.body)`), where `isDone` checks `d===t && t>0` from the `d/t` string. In `paint()`, show per-sprint badge count via `hits(plan.file, s.body, i===0).length` and in detail render `marked.parse(sprint.body) + badges(hits(plan.file, sprint.body, si===0)) + (unlinked not "All tracked" ? "<hr class=ds-hr>"+unlinked(texts) : "")`.

### 3a. Iteration column display (reviewed convention — do not regress)

Sort glob entries newest-first (descending filename) so the latest plan tops Miller column 1 and is the default selection. Vocabulary (user-corrected 2026-09): the page is the **changelog** (`#/changelog`, nav label `Changelog`, unchanged module/manifest/SOP names) and each entry it lists is a **build** — never "iteration" (`buildState()`, drawer `aria-label="Build detail"`); `#/builds` survives only as a redirect alias to `#/changelog`. The accent `.ds-num` shows the plan's time-id, falling back to the filtered-list position when a plan has none, and the card's single `<small>` line carries `DD Mon YYYY HH:MM [– end] · N phases · d/t`. The card line must not repeat that number — it duplicates the accent slot.

### 3b. Changelog IA — cards full width, two-pane drawer (do not regress)

- Base page layout: chips row → `.ds-plan-grid` (single full-width column of iteration cards) → triage/unlinked block. No two-column miller grid on this page — the mid-density two-column `plans | phases` split made navigation hard for the user; entire page width belongs to iteration cards.
- Navigation preference: the user wants phases visible NEXT TO the tasks, not behind a list-then-detail navigation — a single-pane drawer with a phase list replaced by detail (or a back button) is wrong. Drawer is a two-pane panel capped at 50% of the viewport (`width: min(50vw, var(--size-ds-drawer))`): `.ds-rail` (flex 0 0 36%, `Phase 01`-style phase cards at 0.86em with verbatim `Phase N` labels — never `P01` — title + `d/t · commit count` subline only: NO tags line, NO per-card footers) + `.ds-task` pane, plus ONE description footer pinned to the rail's bottom (flex-column `.ds-rail` + `margin-top:auto`; renders the selected phase's description — the same text its hover popover shows — and swaps on rail click). Prev/Next buttons are GONE — the rail is the only phase nav; card click → drawer opens straight onto the task detail with the rail beside it, rail click switches phase in place. ✕/scrim/Escape close. Accent rule (accent when phase done, muted when not) must survive re-layouts — merging card-layout rules has silently dropped it before.
- The drawer's static markup from `render()` keeps BOTH wrappers (`<div class="ds-rail" data-col="sprint">` + `<div class="ds-task" data-col="tasks">`), and `paint()` writes the phase list into `[data-col="sprint"]` and the detail into `[data-col="tasks"]` via `root.querySelector(...)` — never `drawer.innerHTML = ...`. See `references/changelog-rendering.md` for the full retained-node paint contract, the browser interaction-verify loop, TDZ ordering in `paint()`, the cursor-follow tooltip pattern, and line-capped CSS rules.
- Tooltip = one cursor-following fixed `span.ds-cursor-tip` in the static markup; cards carry `data-tip="…"`; a `mousemove` listener on root positions it (swap side near viewport edges, `pointer-events:none`). Per-button absolutely-positioned `.ds-tip` spans are dead weight — do not reintroduce them.
- Click index rule: derive a pick's index from `[...col.querySelectorAll('.ds-pick')].indexOf(b)` where `col = b.closest('[data-col]')` — NEVER `[...b.parentElement.children].indexOf(b)`, because any extra child (header div, non-button) before the cards shifts every index and makes some cards click through to the wrong/no selection. Iterate the verification loop over EVERY card × every rail phase, not just the first card.
- In `paint()` compute `badges(hs)` BEFORE the template that interpolates it and compute the phase's `hits()` before building the task pane — a `const hs` declared after the template that uses it is a TDZ ReferenceError in strict ESM that only throws at runtime (render mounts, first click dies, dev-server HMR masks the crash as silent no-op).

### 5. Styles within budget

`src/ds/ds.css` is capped at 100 lines by `scripts/lint-tokens.mjs` (multi-selector and keyframes one-liners pack fine). Before adding any new block, free lines by collapsing adjacent one-liners (` .a{} .b{}` on one line, keyframes onto the rule line) — count `wc -l` after each compaction, not just once, because the collapse must actually land at ≤100; never just append. Keep `.ds-num` default grey (`var(--color-ink-muted)`) with accent only on `.is-done`. Keep `var(--token)` only outside `tokens.css`; `blur(px)` and `stroke-width` with units must live as `var(--blur-*)` in `tokens.css`. Don't delete a working rule while packing lines (e.g. `.ds-drawer-head button` styles) — verify the diff only merges lines, it never drops selectors.

### 5a. Subset builds — hide hygiene that is not a standalone build

A refactor release often spawns hygiene plans (split-repair, renames, leak fixes) that are technically phased but are NOT shippable entries on their own — the shippable entry is the parent refactor build. Showing each hygiene plan as a separate card fragments the changelog (user sees 14 cards where 12 is correct, with "Repair splits" and "Changelog nomenclature" floating as top-level builds).

When a plan is a subset of a larger build, hide it from the Miller columns via `<!-- changelog: hide -->` placed immediately after the `**Tags:**` line and before the first `---` (the same marker used for build-test and over-limit-split hygiene in `001100`/`235413`). The tracker still links its commits (texts still contains the hidden file, so `hits()` and `unlinked()` stay clean), but `pages-changelog.js` filters it from `plans` (`HIDDEN = /<!--\s*(?:changelog|builds):\s*hide\s*-->/`). Verify after: `All (N)` drops by the hidden count, the hidden titles disappear from `document.querySelectorAll('[data-col="plan"] button b')`, and `ds-track` still reports `0 wip` with the hidden shas counted as linked. Do not retag hidden commits to the parent plan — history rewrite is forbidden; hiding the card is the correct mechanism.

### 5b. Subset builds that belong as phases of the parent release

**Anchor-collision rule (do this before copying):** `hits()` matches with `text.includes(anchor)`, and rendered phase bodies INCLUDE the heading line — so a parent phase numbered 10 or 11 whose heading carries the conventional `{#phase-10}` anchor puts the substring `phase-1` in its body, and every existing commit anchored `phase-1` phantom-badges on it (the rail shows a wrong commit under the new phase). When folding phases 10+, anchor them collision-free (`{#phase10}`, `{#phase11}` — no hyphen) and cite commits the same way; also grep the copied text for lowercase hyphenated `phase-N` strings (a copied `[plan:…#phase-1]` reference inside another phase's block is enough to trigger it) and reword them.

When two builds (e.g. a split-repair and a nomenclature rename) are not standalone releases but hygiene that only makes sense inside a larger refactor release, do not leave them as separate cards with `14` where `12` is correct — make them phases of the parent plan and hide the standalone cards. Procedure: (1) add `<!-- changelog: hide -->` to each subset plan (same marker as §5a) so they drop from `All (N)` but stay linked; (2) append new `## Phase N — <title> {#phase-N}` sections to the parent plan, copying each subset's `| # | Task | Done when |` table and `### Task N: … ✓ done` blocks verbatim, renumbering tasks globally (never restarting per phase) and preserving each original `*Shipped in <sha> · Tasks a–b · phase-N.*` sha; (2a) order the new phases by first execution time (oldest first — e.g. 00:32 nomenclature before 00:45 split-repair) and give each phase a timestamp line immediately under the heading (`*YYYY-MM-DD HH:MM[–HH:MM] · originally <file> Phase N · subset, ordered by first execution.*`) so the drawer shows when it ran and the rail order matches history; (2b) keep that provenance line free of raw ` #phase-N` substrings — write `originally 004508 Phase 1` not `004508#phase-1`, otherwise `hits()` (which checks `text.includes(anchor)`) will cross-match the parent's other phases and the rail will show inflated badge counts (e.g. `23 commits` on a `3/3` phase); (3) keep shipped shas as documentation — do not retag the original commits to the parent file, the parent phases will show `d/t` as `3/3` but with `0` badge count until new commits carry the parent trailer, which is expected (to give a folded phase a real badge, carry a DS file — the regenerated manifest — in the fold commit itself and trailer it with the parent's anchor); (4) verify the parent card now reads the aggregated `N phases · d/t` (e.g. `10 phases · 31/31` vs `6 phases · 20/20`) and the rail shows `Phase 06`–`09` as done, while `ds-track` stays `0 wip` with the hidden shas counted as linked.

- Never add the changelog-hide marker to a new plan without the user's explicit approval — every phased plan renders in the changelog by default, and a silently hidden build reads as a missing build. Historical hides are grandfathered; new ones need an explicit `y` with the reason recorded in the plan.

```bash
node scripts/ds-track.mjs   # prints: "✓ ds-track — N plans · M DS commits (K linked) · W wip · cont <id>"
cat src/ds/changelog-manifest.json | python3 -m json.tool | head
npm run lint:tokens && npm run build   # ✓ 9 stylesheets + 17 JS clean, ✓ 71 modules
# open /ds/#/changelog — Miller detail shows badges when phase has commits; global hr+unlinked only when needed
```
- Headless anchor check before opening a browser — `node scripts/validate-plan-anchors.mjs`. Check the repo actually ships that script first: personal_website does NOT (it MODULE_NOT_FOUNDs), so there the anchor check is `npm run ds:track` (count + `0 wip`) plus the page's "Unlinked DS changes" block. Where it does exist: it ports `chunks/norm/split` from `pages-changelog.js`, accepts optional `<file.md> <anchor>` pairs (else every `.hermes/plan-links.json` entry), verifies each anchor is in the RAW plan text AND in exactly one normalized phase body, and exits non-zero on failure — it catches anchor mismatches and unmarked tasks that `ds-track`'s counts alone never surface. Re-sync the ported `norm()/split()` if the renderer changes.
- Browser-verify the drawer cycle end-to-end after changing the changelog renderer — open card → panes (rail + tasks) → phase switch via rail clicks → close (✕, scrim, Escape separately) must all pass; a stateful module (`sel`) that misbehaves under repeated open/close is the classic regression here. Judge only after a fresh `location.reload()` — HMR state masquerades as a broken handler.
- Diagnose interactive failures on a FRESH page load — after editing a stateful module, a Vite HMR page keeps the old module state (e.g. a half-updated `stage`) and synthetic clicks appear to fail (handler is fine, state disagrees); `location.reload()` before concluding the handler is broken. Keydown listeners on `document` must be simulated with `document.dispatchEvent(new KeyboardEvent('keydown', {key:'Escape'}))` — dispatching the same event on `window` doesn't drive a document-level listener.
```

## 7. Triage next phase when user cites a session ID

User often says `next phase after <session>` where the ID may not exist on disk (typo, future timestamp, unsaved session — or a live Hermes session ID, which lives in the session DB and never greps in the repo). A repo grep returning zero hits does NOT mean typo: run `hermes sessions list | grep <id>` first, and on a match read the transcript via `session_search` and take its closing summary as the resume point. When the CLI is unavailable, fall back to the state DB directly: confirm liveness in `~/.hermes/runtime/active_sessions.json` (`session_id` entries), then read the transcript with `sqlite3 ~/.hermes/state.db "SELECT role, substr(content,1,1500) FROM messages WHERE session_id='<id>' ORDER BY id DESC LIMIT 25"` and the title/cwd with `SELECT id,title,cwd,message_count FROM sessions WHERE id='<id>'`. Inspect schema with `PRAGMA table_info(sessions|messages)` before querying — assumed columns do not exist (there is no `sessions.updated_at`; message order is `id`/`rowid`, and `messages.session_id` is the join key) — and a failed prepare means the column guess was wrong, not that the session is missing. Otherwise resolve without guessing:

```bash
cat .hermes/continuation.json  # canonical anchor + pipeline
ls -la .hermes/plans/; grep -n "^## Phase" .hermes/plans/<active>.md  # available phases
cat src/ds/changelog-manifest.json | python3 -m json.tool | head -n 60  # linked commits vs wip
 git log --oneline -20 -- src/ds src/styles/tokens.css DESIGN.md  # trailers show completed phases
 git status --short -- src/ds src/styles/tokens.css DESIGN.md  # wip = uncommitted next phase
 npm run test 2>&1 | tail -20; wc -l src/ds/*.js src/ds/*.css src/styles/*.css | tail -n 20  # gate + budget
```

Map `git log` trailers `[plan:file#anchor]` to `## Phase` headings, treat `wip` files in manifest as the in-progress phase, and treat missing session ID as `current progress` — report `Phases 1..N done (commit SHAs)`, `Phase N+1 in-progress (wip files)`, `Phase N+2 next (tasks)`, and ask to commit wip before starting next. When the cited ID resolves to a real session, read its transcript first via `session_search` and take its closing summary as the resume point — the failing assert and remaining-work list live only there, never in git state. If the cited session ends mid-work with no closing summary, scroll to its tail and resume from its last tool results plus fresh `git status` / manifest wip — do not chain further back hunting for a summary that was never written. For a `(no code)` / standing-convention phase, completion is judged by adoption (later scopes' trailers + the retro map) rather than code, and it still reads `0/N` until its task lines are marked — state that distinction, then offer the close-out: mark tasks, add the in-force line, retro-link trailing unlinked commits, `ds:track`, commit.

### 7a. Stray-plan triage — plan landed in wrong repo

When `git status` shows an untracked `.hermes/plans/*.md` whose scope clearly belongs to another project (different DS paths, tags, or user says "that was for a different project"), do NOT add a `changelog-names.json` entry or start implementation — verify scope first (`cat` the plan's Goal/Files vs current repo's DS paths), then scrap it: `rm <plan>` + `git checkout -- src/ds/changelog-manifest.json` + `node scripts/ds-track.mjs` to drop it from `manifest.plans` and prove `plan:names`/`ds-track` return to green. A stale cross-workspace draft left untracked keeps `plan:names` red and blocks every later DS gate, so remove it immediately on user confirmation.

When the user asks "is anything pending / what's left" and the gates show only a draft plan, translate the gate output to plain language before the gate jargon: "1 planned feature not built yet: <plan title> — <what it would change> (draft, no code yet)" vs "nothing broken — last push in sync, 0 wip". Gate lines (`plan:names`, `ds:track N/N`) follow the plain summary, not instead of it — the first terse gate-only answer confuses and requires a re-explain.

## 8. Push only on explicit approval — never auto (Vercel storage guard)

Agents never `git push` on their own — every Vercel push burns a deployment + storage. Prepare clean local commits and report what *would* push, then stop. Push only when the user says `y` / `push` / `deploy` / `ship it`.

When the user approves a push, verify readiness first — never push with a dirty manifest:
```bash
npm run ds:track 2>&1 | tail -5  # must be 0 wip after track; if M manifest remains, diff it
 git diff -- src/ds/changelog-manifest.json | head -n 40
# timestamp-only churn (only "generated" changed) → git checkout -- src/ds/changelog-manifest.json; real content change (new sha in commits[] or wip [] cleared) → git add + commit with the active plan's [plan:<file>#{#phase-N}] before pushing
sqlite3 ~/.hermes/state.db "SELECT id,title,last_activity_at,ended_at FROM sessions WHERE id='<latest>'"
hermes sessions list | head -n 5  # Last Active 5m+ = likely idle even if ended_at empty
git status --porcelain; git log --oneline -5; git diff origin/main --stat  # ahead + M/?? to push
```
- `ended_at` is often empty — treat `Last Active >3m` as stopped for Desktop agents; confirm via `git status` wip.
- Stage only DS-tracked paths explicitly (`src/ds/`, `public/images/mood/`, `changelog-manifest.json`) — `.hermes/plans/*.md` is unignored but `.hermes/plans/screens/` and `dist/node_modules` are ignored; never `git add .`.
- Commit with `[session <id>]` trailer when pushing moodboard/DS wip that was not phase-anchored, include `node scripts/ds-track.mjs` before build if `changelog-manifest.json` is dirty, then `git push origin main` and verify `git ls-remote origin main` matches local HEAD.

### 8a. Adopt an idle sibling session's parked wip

When the user reports that something works locally but not on the deployed site, the cause is often another session's uncommitted work: local dev serves the working tree, the deploy serves pushed commits. Procedure:
1. `hermes sessions list | head -n 8` — the owning session shows as "Last Active" hours ago (and its title names the feature) → idle, so its wip is parked, not in flight. Minutes ago means it may still be editing: stop and say so instead of racing it.
2. `git status --short` + `git diff --stat`, and compare against the diff shape you saw earlier — a grown or changed diff means the owner is still writing; a stable one is parked.
3. Attach the change to the plan that OWNS that behaviour surface as a new phase (a hover cue on the changelog calendar belongs to the sound plan, never a new card), stating the mechanism plainly — and re-run the gates and re-verify the behaviour yourself rather than trusting the parked author's intent.
4. Commit with that plan's `[plan:<file>#phase-N]` trailer, close-out marks with your own evidence, refresh the manifest, push — the deployed build only carries what is committed.

Never commit a parked diff raw with no phase, and never treat "it looked finished" as verification.

### 8a-bis. Shared-tree preflight before a plain "commit my changes" ask

A plain "commit any changes" on this repo may land while a SIBLING Hermes session is mid-flight on the same tree (weekly-lump-sum restructures, plan-links sweeps, AGENTS/§5 edits). Diagnose before staging: `hermes sessions list | head -5` (a `personal_website` session "Last Active: just now" with a traceability-ish title) plus `git status --short` — if `.hermes/plans/*`, `.hermes/plan-links.json`, `AGENTS.md` or `src/ds/changelog-names.json` are dirty and you did not edit them, they are the sibling's. Read the sibling's tail via the state DB (`sqlite3 ~/.hermes/state_db "SELECT role, substr(content,1,300) FROM messages WHERE session_id='<id>' ORDER BY rowid DESC LIMIT 6"`) to see whether it just committed; if it did, its files drop out of `git status` and the remaining dirty set is yours to ship. Never stage the sibling's files, never `git add .`, and re-run `git status --short` immediately before each `git add` — the tree changes under you.

Weekly-lump-sum specifics (in force from Sep 21): the catch-all plan is one file per calendar week named for its Monday (`<Mon>_HHMMSS-lump-sum-builds.md`), phases restart at 1 inside it while `### Task N` numbering continues across phases in that file, and the trailer cites the braced anchor (`[plan:<weekly>.md#{#phase-N}]`). A shipment opened before the seal finishes in its opening week's file. Closure is two commits: (1) feature commit covering code + phase marked ✓ done + `docs/graph.mmd`/`arch-schema.json`, (2) stamping commit `chore(lump-sum): close phase-N — stamping <sha>` that replaces `*Shipped in <sha> · Tasks a–b · phase-N.*` — never leave `<sha>` literal and never amend the feature commit to fix its own sha (orphans the manifest).
- A sibling can claim the next `### Task N` in the shared weekly file before you append: re-read the plan (`grep -n "^### Task"`) immediately before writing, number from what the file actually holds, and keep the tasks in numeric order — a duplicated heading silently splits the badge list and the phase's `d/t`. Generated artifacts follow the same rule: while a sibling's edit sits uncommitted, its file makes `verify:atlas` read `stale: <their file> changed since manifest` — that is their gate to green, not yours. Do not run `gen:atlas`/`gen:mechanics` on a tree that is mid-edit (it bakes their half-state into the manifest) and stage explicit paths only (`git add <path> …`, never `git add -A`): a foreign dirty set in `git status` is the expected shape of a shared tree, not a failure to fix.

### 8b. Sanity-commit on request ("why is this uncommitted / just commit and push")

When the user asks to commit parked wip without a scope ("sanity commit"), first run the gates (`npm run build` + `npm run test`) on the working tree — never commit unverified — and check `.gitignore` covers `node_modules/` BEFORE staging: an untracked `node_modules/` in `git status` is both noise and a sweep hazard. No plan phase exists for it: commit as lump-sum slices by concern rather than one blob, so changelog badges stay attributable and each commit gets a coherent one-line subject — slices land in the CURRENT week's lump-sum file (see weekly lump-sum rule), and a slice that only touches portfolio paths still needs that file's `[plan:<file>#{#phase-N}]` trailer when it also moves generated DS files.
1. deps/config (package.json, lock, vite config) — never mixes with feature code, 900-line lockfiles bury real diffs;
2. token source + generated output (primitives, build script, generated tokens) together, never tokens without the generator change that consumes them;
3. feature files (new directories, pages, restyled components);
4. run `npm run ds:track`, then commit the refreshed manifest last — the tracker's `wip` list is status-based, so it only reads `0 wip` after commits 1–3 have landed.
Then push and verify `git ls-remote origin main` matches HEAD. If the diff shape includes plan-owned behaviour, still prefer §8a's phase attachment; §8b is only for wip the user explicitly waives scoping on.

A parked diff whose file headers cite a plan that never existed (hallucinated filename/date, e.g. `[plan:2026-03-15_sound-foundation.md#phase-1]` while no such MD is in `.hermes/plans/`) is usually why it never shipped — nothing could link it, so every gate stayed red. Fix by writing the missing plan under the real slug (`<today>_<HHMMSS>-<slug>.md` with names entry and phases whose tasks are already `✓ done`), re-point every header at it, then ship as two commits (feature + track refresh) carrying that plan's trailer. Re-pointing lengthens line 1 — re-run `lint-manage` after the swap and wrap any header over the 120-char cap into the two-line form (`/* ADAM/DS — path · job ·` / `   [plan:…] */`), keeping the `/* ADAM/` opener intact.

## 9. Execute a multi-phase plan phase-by-phase

When told to finish a plan / work it "phase by phase" until done, run one loop iteration per phase — never batch phases into a single commit. When the order carries blanket permission ("finish all phases", "don't babysit", loop wakeups), treat it as unattended: keep going through every phase with no approval stops, re-check `git status`, manifest wip, and gates fresh at each wakeup — never assume earlier-iteration state still holds — serialize all same-tree work in this session, and report one concise iteration summary per wakeup, ending with LOOP_COMPLETE on its own line only when every phase is shipped and gates are green:
1. Implement only that phase's `### Task` blocks and files.
2. Gate per phase (`npm run test`) before touching the next — a single gate at the end hides which phase broke.
3. `git add` that phase's files by name and commit with a `[plan:<file>#Phase-N]` trailer; leave pre-existing unrelated dirty files uncommitted and confirm via `git status --short` they stayed out.
3a. Capture step — end every task by routing what it taught so future changes adhere without being asked: universal laws (gates, budgets, ports, commit shape) append one bullet to the repo's convention file; procedures and pitfalls patch the governing skill via `skill_manage` (one rule + why, never incident narration); phase context (why a split point was chosen) goes to `docs/decisions/NNN-<slug>.md` in five lines (context, options, decision, why, consequences); one-offs stay in the task report only. File the capture in the same commit as the task it governs, newest entry wins on disagreement with a citation of the superseded one, and verify the ledger at handoff (every decision linked, no dead rules).
4. Close-out after each phase (incremental, not just final): append `✓ done` to that phase's `### Task` headings, add a `*Shipped in <sha> · Tasks a–b · <anchor>.*` line under its `## Phase` heading (anchor must appear verbatim so `hits()` matches), re-run `node scripts/ds-track.mjs` + `npm run test`, and commit the plan doc as a `chore` with a single-anchored `[plan:<file>#phase-N]` trailer. After the final phase, also commit with `[plan:<file>#Shipped]` if needed — never leave a shipped phase reading `0/N` waiting for the end.

See `references/lint-smoke-gates.md` for the Phase 0 freeze gate pair (`lint-manage.mjs` + `smoke.mjs` on 5199) and `docs/baseline.md` template — the 13-file inventory, `fileURLToPath` pitfall, and smoke marker/port rules.

## 11. Smart changelog — tags, chips, suggester

- Closed taxonomy (`src/ds/changelog-tags.js`): Design System, Component, Function, Motion, Layout, Tooling — never invent new tags, map to these. Plan preamble carries `**Tags:** a, b`; any phase overrides with `*Tags: a*` under its `## Phase` heading; untagged phases auto-infer from keywords (fallback Design System).
- Renderer (`pages-changelog.js`): chip row filters plans+phases (OR, multi-select, counts per tag); Iter N derives from the FILTERED list client-side — never hard-code iteration numbers, they renumber on filter.
- SOP (repo README § DS conventions): large prompts (≥40 words, ≥2 task verbs, or ≥2 areas) get a phased tagged plan FIRST via `npm run plan:suggest -- "<prompt>"`; small prompts implement directly. `ds-track` prints `(x/y tagged)` coverage — untagged phased plans are triage items.
- Retro links (`.hermes/plan-links.json`, applied by `ds-track` at manifest time, newest-first, no history rewrite; it overrides a sha's existing trailer, so it can also re-point a mis-cited commit): map each pre-trailer SHA to `{plan, anchor, note}` where the anchor passes BOTH renderer checks — verbatim in the RAW plan text (else the commit stays in "Unlinked DS changes") and in exactly ONE `norm()`-transformed phase body (else `hits()` badges zero or many phases). `null` = first phase. Multi-area commits badge on the dominant area with the span in `note` (e.g. "spans P1 AA re-proof / P4 list -> badged P2 materials"). Validate every candidate before writing with `scripts/validate-plan-anchors.mjs`. Phaseless legacy plans get one appended `(retro)` shipped phase with `- [x]` items + `*Tags:*` instead of restructuring.

## 12. Coverage audit — commits the manifest never saw

`0 wip` does NOT mean everything shipped is linked. The tracker's log is DS-path filtered and (by design — see the plumbing rule) drops commits whose only DS-path change is a generated file, so invisible are: style/view work (`src/styles/*` outside `tokens.css`, `src/views/**`, `index.html`), plan-only close/stamp commits, and `chore(ds): track refresh` commits. Weeks of UI phases can ship while the changelog stays frozen, and the user notices ("my commits aren't documented") before any gate does.

Audit before ship reports on UI-heavy batches, and whenever the user says commits are missing:

```bash
# shas in history but not in the manifest — run from repo root
python3 - <<'EOF'
import json, subprocess
have = {c['sha'] for c in json.load(open('src/ds/changelog-manifest.json'))['commits']}
out = subprocess.run(['git','log','--format=%h|%s','--since=<YYYY-MM-DD>'],capture_output=True,text=True).stdout
print('\n'.join(l for l in out.splitlines() if l.split('|')[0] not in have) or 'all tracked')
EOF
```

Fix — retro-map into `.hermes/plan-links.json` (the only sanctioned channel; never rewrite history):
1. Parse each missing commit's own subject trailer `[plan:file#phase-N]` → entry `{plan, anchor: "#phase-N", note: <subject>}` — the trailer is already correct, the tracker just never saw the commit.
2. Trailer-less commits (early feature commits, close/stamp marks): grep `.hermes/plans/` for the sha — the plan whose `*Shipped in <sha>*` line contains it names the anchor.
3. Rewrite plan-links one line per entry, re-run `node scripts/ds-track.mjs` → missing drops to 0 and the count jumps (e.g. 223 → 256); commit plan-links + the regenerated manifest together with the covering plan's trailer.
4. The retro commit and its close are themselves invisible (plan-links is not a DS path) — one trailing straggler is the steady state, caught by the next pass; do not loop chasing it.
5. Pre-trailer commits (subject carries no `[plan:]` at all): resolve each sha by subject + date to the plan whose scope matches — for a phaseless legacy plan, append a `(retro)` phase first — then validate the anchor like any other. Appending a `(retro)` phase flips that plan into the tracker's `tagged` denominator, so give the plan a PLAIN preamble `**Tags:** …` line: the regex is line-anchored, so `> **Tags:**` inside the header blockquote never matches and `ds-track` then reads N-1/N tagged (red gate). Its `changelog-names.json` entry is usually already curated.
6. Expect the missing set to be dominated by four kinds — plan-only close/stamp chores, `chore(ds): track refresh` commits, plumbing-excluded commits (their only DS-path file is generated), and pre-trailer UI/CMS commits — and expect exactly ONE straggler after the pass: the pass's own close/stamp commit, which the next track refresh picks up. Do not chase it: mapping it only moves the straggler one commit forward.

Verify: re-run the audit (0 missing) and spot-check injected records for non-null `plan`+`anchor` in the manifest.

## Plan-doc format for changelog scan

The changelog detail pane renders raw plan markdown, so author phases for scanning, not reading:
- One italic summary line under the `## Phase` heading, then a `| # | Task | Done when |` table (required even for lump-sum retro phases — the table is the scan anchor, the tasks are the detail; a phase with only `### Task` blocks reads as a wall of text and the `norm()` bullet becomes kilometers of inline detail), then one `### Task N:` block each with an italic timestamp line `*YYYY-MM-DD HH:MM · sha · subject*` immediately under the heading, then one-line `**Objective:**` / `**Files:**` / `**Verify:**`. The timestamp line is what the screenshot's per-task commit block expects — without it the badge list at `marked.parse(s.body) + badges(hs)` is the only time signal and portfolio commits that were not retro-injected have `hs.length===0` so the phase renders with no commits at all.
- Never use `>` blockquote for the summary — it renders with a left indent that reads as stray padding in the detail pane; use `*...*` instead.
- When opening a continuation/superseding plan, mirror the superseded plan's phase shape (same `## Phase N` numbering + hidden `<!-- {#phase-N} -->` anchors) so per-phase counts render in the tracker with no rewrite — a renamed phase scheme (A/B/C vs 00–06) costs a full plan rewrite after the owner rejects the unfamiliar shape.
- Number tasks globally unique across the whole file (1–N, never restarting per phase) — duplicate numbers break scan and the per-phase progress display.
- `hits()`/tracker match anchors by regex on the COMMIT SUBJECT, never by heading rendering — so `{#phase-N}` need not sit literally on the heading line. A renderer that paints the body with plain `marked` prints a trailing `{#phase-N}` on a heading as raw text (it only honors the syntax with an anchor plugin): put the anchor in a hidden `<!-- {#phase-N} -->` comment under the heading instead — still verbatim in the raw text for `text.includes(anchor)` matching, invisible in the render.
- A markdown table must be preceded by a BLANK line: an italic `*summary*` line directly above `| # | Task | Done when |` makes `marked` swallow the table into a pipe-laden paragraph blob in the detail pane. Summary line → blank line → table, in every phase.
- When a phase gains tasks, renumber the tail in the same edit; grep `^### Task` first to list current numbers.
- Ontology: plan is EITHER flat Tasks (`## Task`) OR Phases containing Tasks (`## Phase` + `### Task`). Never 'items' — canonical word is 'tasks' everywhere.
- Iterations are Evals, not new Phases: polish/bug-fix/style tweak on shipped task = revision/eval (plan-history snapshot + gate · rev), not new `## Phase`. New Phase only for new scope.
- Engine invariant: every phase renders with consistent status line (tasks fraction or DONE + gate verdict).

## Pitfalls

- A plan whose fenced code block contains `^## ` lines (e.g. proposing AGENTS.md sections `## 5. …`) breaks a naive `chunks()` split on `/^## /m`: the phase body is shredded mid-fence and the rail reads a partial `d/t` (0/1 on a 3-task phase, plan card total wrong). Keep `chunks()` fence-aware (toggle on `^\s*``` `, only split outside fences) and verify with a before/after parse diff across every plan — exactly one plan should change.
- When closing out a phase, verify the changelog rail per phase (not just the code gates) — the archive's `d/t` + badge counts are part of the phase's evidence, and renderer regressions surface only there. Badges lag by one commit: the chore carrying the manifest never shows its own sha until the next refresh.
- When closing out a plan where some tasks were deliberately dropped, do NOT leave them unmarked (they read as debt under an unmarked-task sweep) and do not mark them done — introduce a `✗ cancelled` status appended to the `### Task N:` heading plus a one-line `> **Cancelled by user override** — <reason>.` blockquote beneath it. Cancelled tasks stay in the plan (the plan is history, not a todo list), carry a real reason, and future sessions must never re-propose them. Perf-optimisation plans often cancel the asset-compression task while shipping the code tasks — record the KB baseline the cancelled task targeted so the loss is visible.
- Renderer-side (when `norm()` in `pages-changelog.js` synthesizes the checkbox): cancelled ≠ done visually.
