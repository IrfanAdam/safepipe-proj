# Interactive 3D Data Views

## When to Use
Load this skill when a task involves an interactive three.js scene used as a data view: digital twins, monitoring tables, dotted-trace networks, click/hover selection over 3D assets, or headless verification of such scenes.

Three.js monitoring scenes (pipeline twins, tactic tables): dotted-trace rendering that stays crisp on zoom, picking that hits what the user aimed at, and hover that previews the click target.

## Two layers at one position — audit both modules' build contracts
When two modules both render the same logical object (facility outlines in the network module + a structures module both drawing boxes at `fac.position`), deleting one layer is not enough — inspect the survivor's own build contract: a `mass()` helper that ignores its declared params and unconditionally adds a default element (e.g. a flat disc) keeps the wrong look alive after the fix. Grep both siblings for cross-imports (a network module importing terrain VEX to drape its traces copies terrain coupling into unrelated code) before changing either.

## Dots stay round — sprite map is mandatory
Render dotted traces as `THREE.Points` with a `CanvasTexture` radial-gradient sprite assigned to the material `map` — untextured points render as squares, which read as pixelation the moment the user zooms in.
- Generate the sprite once (128px canvas, white core fading to transparent edge) and share it across materials; color still comes from the material.
- Confirm with a zoomed headless capture, not by reasoning about it — squares only show up close.

## Picking — proxies, fat radii, kind ranking
Never raycast the dots themselves. Build invisible proxy geometry per asset (fat tubes around polylines, padded boxes around facilities, enlarged spheres around markers) and raycast only that set.
- Size proxies for fingers, not geometry: tube radius ~0.6 world units reads fairly at glancing angles where thin tubes always miss.
- Rank overlapping hits by asset kind (discrete markers and facilities above line tubes within a distance tolerance) — closest-hit alone lets a fat tube wall steal clicks from a box sitting on the line.

## Hover must preview the click target
Without hover feedback every click feels erratic, even when picking is correct: add `pointer` cursor plus a visible target swell (dot size gain, node scale-up) on mousemove, cleared on mouseleave.
- Gate hover updates on change (skip re-apply when the hovered id is unchanged) so mousemove stays cheap.

## Verify on a temp server you re-probe
Serve on a port the user does not own, wait for HTTP 200 with a readiness loop before capturing, and re-probe before every capture — temp servers die silently and a dead server produces a missing file, not an error render.
- Capture with SwiftShader flags headless, then vision-check the pixels (dot roundness, zone dashes, no blank canvas) before committing.
- Confirm the server serves fresh bytes after every rebuild: curl the changed file from the running temp server and grep for a change marker before trusting probe results — a live server can answer 200 with pre-rebuild code after a reload race, and a green capture against stale bytes proves nothing.
- Isolate stacked layers by toggling exactly one layer visible/invisible and pixel-diffing the two captures (mean abs diff + % changed pixels) — a large diff proves the layer paints, a zero diff proves it is dead regardless of what the state readout claims.
- Drive probe cameras with arrays or Vector3, never plain `{x,y,z}` objects: fly-to paths spread positions into `Vector3.set(...pos)`, where a plain object throws — usually swallowed by a guard, so the camera silently never moves and the capture passes at the wrong angle. Read the camera position back after every scripted move.

## Container-agnostic mounts own their canvas sizing
A canvas with no CSS size stays a 300x150 box while the renderer buffer and the raycast rect use the container size — the image renders squished and every pick ray is wrong. Set inline `display:block; width:100%; height:100%` at mount time so owners need no stylesheet.

## Gallery multi-specimen — lazy-mount hidden panels
When a gallery hosts multiple WebGL specimens (one per tab/panel with `hidden`/`display:none`), never mount a specimen while its panel is hidden — a hidden container reports 0×0, so the renderer creates a 0×0 buffer and stays black even after the panel is shown, and each hidden mount wastes a WebGL+MapLibre context (2 per specimen) that exhausts mobile GPU limits. Mount each specimen lazily on first reveal (check `panel.hidden` before `createTwin`/`initSatBase`, trigger via tab click and `hashchange` plus an initial `maybeMount()` after imports), and on reveal re-measure with `getBoundingClientRect` then call `renderer.setSize(w,h)` and `map.resize()` (or `ResizeObserver`) so a 0→visible transition paints correctly.

## Clicks: guard drags, centre the clicked point
- Orbit/pan drags end in a `click`: record the pointerdown position and ignore presses that travelled more than ~6px, so only deliberate taps drill down — otherwise every pan flies the camera.
- Drill-down flies to the asset anchor (fault chainage, else midpoint / position) — the SAME point the level buttons aim at and where the beacon, halo, and labels live. Never aim the raw click point: the orbit target always projects to exact screen centre, so a click-aimed camera centres tapped dirt while the markers sit corners away, and only the buttons look correct. A radius-snap hybrid (exact click inside ~1 unit, anchor outside) still strands markers up-line on long assets — consistency beats cleverness, ship anchor-always. The ground-plane ray intersection still matters for missed taps (AF focuses the tapped dirt) and must sample the SAME height field the terrain renders — a hard-coded y=0 plane sinks the point under hills.
- Docked panels cover the frame centre: when a detail panel occludes one side of the canvas, translate camera AND target by the same lateral vector along camera-right so the focus projects to the free-area centre instead of under the panel. Free-area centre in NDC-x equals minus the occluded width fraction — NDC spans 2.0 across the full width, so bias = −fraction, not −fraction/2. Clamp the bias (~±0.3) and recompute it per flight from live container size, since opening/closing the panel changes it; orbit geometry survives because both endpoints move together. Only compensate when the panel actually covers the focus — when the user asks for exact frame centre, ship bias-zero and prove it with a measured capture (focus-disc edges equidistant from the frame sides); a clever offset against a non-problem reads as off-centre.
- Fly-to vs damping fight: OrbitControls damping keeps drifting target/position during a scripted tween, oscillating the arrive point — disable damping (or skip `controls.update`) for the fly duration, then re-enable. Scale fly duration by distance (map→asset ~1200–1600 ms, never a flat 600 ms) so long descents stay followable.
- Probe camera focus state before diagnosing aim inconsistency: prefab presets, cage clamps (`maxDistance` re-frames the shot when the pan clamp rescales), and limits like `maxPolarAngle` clipping a plan-preset pitch can each independently move the target — dump current target/position + active preset before tuning aim code.
- Label view controls with spatial words users already know (Top / Iso / Near), never internal level numbers.
- A level change with nothing selected must dolly into the current orbit target in place — never resolve a hardcoded fallback asset. A `lastId ?? FALLBACK` in the set-level path teleports to an unrelated model and reads as 'the view button jumps to another model'. Keep fallback ids for deep-link boot only, and cover the empty-selection path with a regression test asserting the target holds.

## Match the reference idiom before adding realism
When the reference renders real objects as outline holograms, 'more realism' means believable arrangement plus denser detail in that same idiom — switching to shaded solid masses reads as toys against a hologram, not as fidelity. Confirm the idiom (outlines vs solids) against the reference before rebuilding any material.
- Additive hologram layers (contour lines, glow points, rings) get `fog: false`: scene fog only dims additive blending toward invisibility at map range, so the layer vanishes exactly where the map view needs it.
- When generated detail (contours, instances) fails to appear while sibling objects render, check the data before the renderer: a flatten/mask step may have zeroed the field across the visible region, leaving the extractor no crossings and an empty buffer.

## Selection survives declutter; status color lives on hover
Level-of-detail ghosting must exempt the selected and hovered assets: when drill-down hides labels, rings, zone fills, beads, or flow at close range, the thing the user drilled into keeps its full highlight at every level — zooming in must never dim the target, or selection reads as broken at the exact moment of focus. Implement the exemption per layer (selected id bypasses the ghost factor; hovered id bypasses dimming), not as a global opacity lift.
- Reserve saturated status color for hover and selection only (green safe / red alert halo at low opacity while the cursor rests on the entity): the resting map stays neutral so attention lands where the pointer is, and the palette never shouts at an operator who is only surveying.
- Tier label visibility by range: map range shows rim/destination tags plus faulted, selected, and hovered assets only; the full label set appears in-field at drilled-in levels. A pill for every asset at full-map distance is noise, not information — restraint is what makes the hovered label readable.

## Traces: solid walls beat dots at map range; dashes alone carry flow
Dotted pipeline traces fragment into noise at full-map distance — when routing readability matters more than per-node texture, render pipes as solid fat-line walls in the health color (surface runs solid, buried runs dashed + dimmed), and carry flow direction with animated `dashOffset` drift on a thin overlay alone. Extra direction markers (cones, chevrons, arrow polygons) are redundant once dashes move — delete them rather than tuning them, they never win against the clean line.
- Keep the flow overlay subtle (opacity ~0.3): it is ambient motion, not an alert channel.

## Contours must plot elevation, not decorate
Contour lines that wander without closing read as texture. Make every line defensible as surveying:
- Elevation-ranked glow: the highest contour glows most, fading downslope — brightness × width scaled by level rank (e.g. 0.72→1.32, summit 2.7px vs base 1.15px), capped below alarm luminance so faults keep leading. Whisper opacities (0.28 base / 0.55 index) hold; test the caps so a later bump cannot silently white-out the terrain.
- Water is never a flat slab: lake + river stay flat fills at one level Y, but carry blue pseudo-contours (isobaths/wave lines) inside the fill — concentric rings for lakes, offset sinuous lines for rivers — all in WATER_COL (the only blue), shore/drain lines stay neutral grey. Count WATER_COL uses as ≥2 (fills + waves), not exactly 2.
- Volume without extrusion: bake NW-sun hillshade from the sampled H grid (central differences × VEX → dot with sun) and modulate vertex colors × fill tint; derive shade and height samplers bilinearly over H with zero extra field() calls so VEX and relief gates cannot drift.
- Give the field localized relief the rings can close around: place 2–3 gentle gaussian hills in the gaps between data corridors (never under the focus assets), plus one hollow and one incised draw. Broad swells alone never close a ring inside the map.
- Two tiers: dim base lines + brighter, thicker index line every Nth level. Index lines carry the elevation reading.
- Number the index rings inline, OS-plate style: small mono readout on a dark pill sitting on the ring, 2–3 tags spread along the longest rings per level. Tags at full-map distance must be large (asset-pill scale); shrink them on drill-in via the detail level so close-ups stay clean.
- Carve valleys with steep banks so contours kink into upstream Vs around the water for free (marching squares does the work — never hand-draw Vs), and run a faint blue drainage thread along the valley bottom with short feeders off the high ground.
- Alternative that removes the body fill entirely: neon-plate void — no landmass mesh at all, additive glowing rings on black with boosted bloom. Cheaper than shading and strictly more legible; dim rings + shrink tags on drill-in so the selection owns close-ups.

## Every capability needs a visible control
A feature reachable only by keyboard shortcut or URL param does not exist for the operator — the moment a user asks 'where did X go' about a working feature, add a clickable HUD toggle for it (cycling button with active state) wired to the same setter the shortcut calls. Discoverability is part of the feature. Park secondary legends behind an icon (like `?` → `▣`) hidden by default — `ops-hud__legend--hidden` toggled by a button — so the map stays decluttered until requested. Scale bars must be dynamic: derive km per bar from camera frustum (`distance * tan(FOV/2) * aspect / canvasWidth`) and round to 0.5/1/2/5/10/20, updating each frame — a static per-level label reads as unknown information once the user zooms inside a level.
A clickable HUD readout must defeat the overlay's own click-through: HUD roots run `pointer-events: none` so canvas drags pass through, which silently swallows clicks on any div banner — build the readout as a real `<button>` with `pointer-events: auto` plus `cursor: pointer`, wire it to the same `select(id, { fly: true })` setter the search box calls, and carry the target id in `dataset` so the state refresh that rewrites its text refreshes the target too.
Geometry sunk below an opaque terrain body vanishes entirely where the surface runs high — depth only reads where the ground happens to be low. Render buried runs as an x-ray plan projection instead: blend each sample's height from the surface trace to the draped terrain height by the burial factor (sample the same field function the terrain uses, plus a small offset), keep the run dashed and dimmed, and mark each dive point with an explicit surface marker in a cool contrasting color so the eye sees exactly where the line leaves the surface.
- Ground-sit every overlay once relief is real, not just pipe traces: fault kits, halos, beads, sensors, structure runs, and label anchors all float at flat datum or bury in hillsides until each samples the same field function the terrain renders. Audit the whole overlay set in one pass — fixing traces alone leaves the kit buried and the scene still reads as floating decals.
Depth of field must be real optics, not a screen-space blur band: attach a DepthTexture to the scene render target (no extra scene pass — it only exposes the buffer already rendered), compute per-pixel circle-of-confusion from the thin-lens formula against actual depth, and spiral-gather the bokeh in the composite pass. Expose genuine camera inputs — aperture in real f-stops, focal length in mm driving the actual camera FOV, focus distance in world units — behind a single focus icon that opens a hidden panel (F key too); no sliders live in the open. Keep auto aperture deep at map range (ƒ/8 holds the map sharp) rather than killing DoF outright when the user wants DoF on by default. Autofocus tracks hovered asset → click point → selection → orbit target, re-measured every frame so it holds through fly-tos. Keep the pure math (fov-for-focal, CoC-in-px) in the camera module and unit-tested: derive expected magnitudes from the formula, never invent them — honest output (wide glass keeps deep background sharp past hyperfocal) fails made-up thresholds on correct code.

## Real-world grounding: pin region, vector map, hex sectors
When the user asks the twin to sit on a real place with real data, pick assets by license + keylessness verified at source, and keep one shared id across 2D and 3D:
- Terrain: fetch 1° SRTM GL1 30 m GeoTIFF tiles from the OpenTopography S3 mirror in-browser with geotiff.js (CORS open, no account) — real elevation beats any hand-tuned procedural field for believability; keep a `terrainSource: procedural|dem` seam so the synthetic field stays a fallback.
- Water level follows the local sea datum, never a hard-coded 0 — endorheic seas sit far below global MSL (Caspian ≈ −28 m), so a `sampleH < 0` shoreline test strands water inland of the photo coastline by the whole 0-to-datum band; threshold water at the local sea level and keep the constant named next to the site pin so the next site re-derives it instead of inheriting it. Then verify the DEM's actual near-shore fill against the nominal datum before using it literally — clamped bathymetry can sit above the datum (Terrarium holds Caspian shallows at exactly −27, so a literal `< −28` test erases the sea); set the threshold midway between the coastal-plain floor and the fill with margin both sides, and pin a dry-inland plus a wet-offshore point in a regression test.
- 2D basemap: MapLibre GL JS + deck.gl `MapLibreOverlay` on CARTO Dark Matter vector GL style — raster CARTO tiles are deprecated and now key-gated; vector styles need a free instant-emailed key (5M tiles/mo). OSM raster tiles and Esri World Imagery remain keyless fallbacks (satellite toggle). Leaflet is raster-only, wrong for vector tiles.
- Real features: OSM Overpass (`overpass-api.de/api/interpreter`, `[out:json]`, `out geom`) gives `man_made=pipeline` corridors with substance/diameter/operator — budget ~100 queries/<10 MB per day for recurring apps, cache hard; query via GET with `--data-urlencode` (POST returns 406 on the main instance), 406/429 → pause 30 s with backoff, 500/timeout → retry then try mirrors. Coverage is NA/EU-weighted and trunk-only: label every asset `source: 'osm'|'parametric'|'synthetic'` so synthetic detail never masquerades as surveyed.
- Sector id: tessellate the operating region with `h3-js` `polygonToCells` at res ~7 (~5.2 km hexes); the hex id is the ONE key shared by map layer, twin feed, work orders, crews, sim, and approvals, so map↔twin handoff is a single URL param and selection survives the round trip.
- Free-data pins verified for twins: Open-Meteo `/v1/archive` (weather to 1940, no key non-commercial), USGS FDSN earthquake GeoJSON (no key, open CORS), NASA OPERA DISP-S1 InSAR displacement time series via ASF DAAC (research-grade; seed a proxy series until creds). Physical models: Poly Haven `modular_industrial_pipes_01` is the verified CC0 exhaustively-detailed kit (runs, elbows, tees, flanges, valve+gauge, 8K PBR, 12k tris); Sketchfab licenses vary per-asset and OpenGameArt has no real industrial kit — do not treat either as blanket-safe.
- Health `update(feed)` must not crash on first live data flip: gains/size constants used inside update paths must be defined at module top, and a feed-shape test (TDD) guards the contract before code — an undefined constant inside `update` turns the twin's own demo data switch into a runtime throw.

## Rate procedural terrain against free ground truth before claiming realism
Eyeball side-by-sides never catch amplitude errors — a valley can read right at 70% of its real depth. Ground every realism claim in numbers:
- Open-Meteo `/v1/elevation?latitude=..&longitude=..` (keyless, Copernicus 30 m, no account, no GeoTIFF parsing) returns real elevation for any point list — fetch a small grid (5×5 over the site window) as ground truth in seconds.
- Measure the procedural field on the same window and report each stat as % of real: total relief (max−min), standard deviation, valley-wall depth (river-center vs ±6 km at several latitudes), and E–W wall asymmetry. Shape-right/amplitude-under (~60–70% of real) is the usual outcome; the fix is deepening walls and lifting plateau variance, not reshaping the valley.
- Lock measured values as regression tests with bands around current readings (tighten bands as fidelity improves, never to hide the gap), label ground-truth constants with source, and write per-task 0–10 ratings next to the plan tasks. Track known geo bugs as `it.todo` naming the fix plus its re-rate condition — the suite stays green while the gap stays visible.
- Never map a whole-tile pixel grid onto the site window: a 1° SRTM tile spans ~111×60 km at mid-latitudes about its own center, so squeezing it into a smaller site extent lands altitudes tens of km off. Always build the pixel→world affine from the image origin+resolution, window the site extent out of the tile, and sanity-gate decoded relief against the known real relief — a near-zero gate passes flat tiles.

## Map↔twin registration parity (2D satellite behind the 3D canvas)
When a real 2D map sits behind the twin canvas with a crossfade, the layers must share center, scale, and orientation or every pan/zoom slides them apart:
- Reuse the codebase's existing world→geo mapping — grep for the sampler that converts world km to lon/lat and copy its axis signs and projection verbatim. Deriving north from camera presets invites a 180° flip; the sampler is the convention's source of truth.
- Center follows the orbit target: every twin pan moves the map center by the same equirectangular offset. A center pinned on the site reads fine until the first drag, then layers diverge.
- Zoom from ground resolution, never orbit distance: twin span (`2·dist·tan(fov/2)`) over viewport height gives m/px — distance-only heuristics sit multiple zoom levels off and the crossfade jumps scale. MapLibre zoom is the 512-px-tile convention: `mpp = 78271.51696·cos(lat)/2^z`; feeding it the 256-convention constant (`156543.03392`) renders the base exactly 2× too tight (measured: z12 at 57.03N → 10.398 m/px, not 20.80). Put NO slant factor in the zoom input — at pitch the map projection itself foreshortens, so scaling mpp by `1/sin(elev)` masks the convention error at oblique angles while breaking TOP-down (with both errors fixed: 0.3–1.4 px rms registration at every elevation; with either left in: 35–78 px at TOP poses, 78–244 px oblique). Re-check every zoom clamp against the corrected values — a floor tuned to the old too-tight numbers silently re-breaks the fixed view by one level.
- Bearing from orbit azimuth under the same axis convention — and mind the sign: with +x east / +z south world axes the view azimuth is `atan2(-dx, dz)` (dx/dz = cam − target); `atan2(dx, dz)` mirrors across N–S and spins the map opposite the orbit. The mirror is invisible exactly at yaw≈0/180 (dx≈0), so 'both views read north-up at TOP' proves nothing — discriminate at a non-axis yaw (e.g. 45°), where the mirrored candidate wins at every pose while the wrong sign costs 30–50 px rms at TOP.
- Satellite stays true-color: no raster brightness/saturation/contrast shifts and no tinted hillshade shadow/highlight colors — tinted shading reads as thermal or false-color imagery. Keep hillshade gentle and neutral.
- Match the vertical axis too: MapLibre `setTerrain({exaggeration})` must equal the twin VEX the overlays drape at — mismatched scales float pipes above real ridges or sink them into valleys at drill-in range, where metres-per-pixel make the gap visible. Export one shared constant and assert numeric equality with the terrain VEX in tests.
- Pair imagery with a keyless reference overlay (places/roads/boundaries — Esri World_Boundaries_and_Places rides the same host as World Imagery): a bare photo reads as an unfinished base, labels are what make satellite read as a map.
- Registration is not feature match: state plainly when twin features (water, corridors, structures) are synthetic or schematic — no sync math aligns them with real imagery. Name the missing inputs (DEM-derived placement, real vector import) instead of implying parity.
- Prove registration numerically, not by paired captures: project the same world points through both systems (`map.project(twinTargetToLatLon(P))` vs the twin's own pinhole projection), report screen-px rms/max over a central-ring grid — captures prove presence, never scale or orientation. Sweep poses AND orbit azimuths: at every azimuth the map bearing must equal −yaw mod 360 (dBear 0.00°) with rms flat across the family — a sign error that hides at yaw 0/180° reads as a constant offset in the sweep. Method, pitfalls, and runnable probes: `references/registration-probe.md`, `scripts/registration-probe.cjs` (pose sweep + verbatim-vs-old A/B), `scripts/orbit-sweep-probe.cjs` (azimuth parity). A lens/disc that masks the base into the canvas is twin-side geometry only — its rim matching the bezel cannot clear the imagery's scale or rotation beneath it.
- Cut the clip in the coordinate space that owns the content: a mask drawn through the twin camera misregisters against map content rendered through the map camera (tens of px at oblique pitch — measure it by projecting the same world ring points through both cameras and diffing screen px), so photo leaks past the hole wearing the content's own square tile corners. A fill/clip layer inside the map conforms to map terrain in map space by construction, so its edge stays a world circle under every projection; keep the twin-side feather only as a soft edge over the map-side cut. Size the lens at the full mapped ring at every site — a disc scaled to the site's DEM window sits far inside the ring and strands pipes on black outside a cutout that reads as a pasted patch; the DEM extent bounds surveyed relief, not the lens.
- Verify a map↔twin crossfade slider at four stops, not just the ends: capture 0 (pure map), 50 (registered blend — coastlines and roads must cross the blend boundary with zero offset), 100 TOP-down, and 100 oblique. Demand zero photo pixels at 100 at ANY pitch — a 'satellite stays at TOP' rule that keeps imagery under full-twin contradicts the slider's promise and reads as bleed. Back each stop with a pixel-diff number (e.g. terrain-on vs off % pixels changed), because a slider that moves with no pixel delta is a dead control regardless of what the state readout claims.

## Black renders in the user's browser — ship the diagnosis, not a guess
A black panel on the user's machine that renders fine in headless probes is an information problem before it is a rendering problem: make the next screenshot carry the failure instead of asking for console logs.
- Paint staged boot status as plain DOM before awaiting anything networked: twin/map/mixer chrome must exist even when tile or worker fetches hang, with each stage named (`boot: twin ✓ · map: loading…`) so a screenshot shows exactly how far boot got. Race map mount against a timeout (e.g. 30 s) that writes `map FAILED: <reason>` into the same status line — a hang with no message is the failure mode being eliminated.
- Mount-critical code must need zero imports: an iframe `src` assignment or first-tab mount living in the same inline module as heavy static imports dies with them — one dead import blacks out every tab with no message. Put the mount first with no imports, convert the heavy stack to dynamic `import()` inside an async iife (top-level `await` in an inline module fails the production build transpile), and paint import failures as text into the dead panels.
- Add a classic (non-module) error overlay to standalone harness pages: `window.onerror` + `unhandledrejection` handlers appending to a fixed div run even when the module below never loads, plus a timed `STILL LOADING @ +10s` note when no canvas exists yet.
- Listen for GPU death explicitly: `webglcontextlost` on every 3D canvas (twin + map) paints a verdict div, and a persistent `map.on('error')` ring (last 5) feeds the status line as `MAPERR:<msg>` — tile/source failures after `load` and context loss otherwise read as an unexplained black map.
- Reproduce degraded-network symptoms with fault injection at the request-routing layer: kill tile hosts one by one and assert the UI state. Test abort (instant error) AND hang (never responds) separately — a hang gates `load`/ready events forever while fast failures still fire them, so the two produce different dead states and only one reproduces the user's symptom.
- Guard WebGL construction: wrap `new THREE.WebGLRenderer` in try/catch that leaves a readable in-container verdict and rethrows, so a context that can never be created differs visibly from one that renders black.When the twin rebuilds itself (DEM-swap remount, level rebuild) and appends a fresh canvas, every piece of state the old element carried — crossfade opacity, scope masks, ground-ownership mode — silently resets to defaults while the mixer still reports the old value. Detect the swap by canvas-element identity on the sync tick and re-apply the full mix the moment it changes; the scene-background fan-out alone covers the clear color, never the element opacity.
- `Object.assign(api, fresh)` copies data flags but not behavior: copied setters close over the fresh internals, so a mode flag read from the live handle goes stale while the fresh mesh obeys. Capture the kept mode before the assign and re-assert it (flag plus setter) after.
- Liveness guards need a release path: a safe-default floor held while a dependency is missing (e.g. effective mix floored until the map object exists) must explicitly re-apply when the dependency lands — nothing re-runs the mixer on mount by itself, so the floor sticks forever and the control reads one value while rendering another. Re-apply the full state inside the mount-resolution handler.
- Fade materials, not the shared canvas: when a persistent layer (clip mask, vignette) lives on the same canvas as fading overlays, lock canvas CSS opacity at 1 and carry the whole fade in per-material emphasis down to true 0 — canvas opacity would take the persistent layer with it.
- Degradation must reclaim, then self-heal: when tile stacks fail underneath an explicit user choice of that side, reverse the choice toward the live side with an honest tag (a stranded transparent layer over a layerless map is the black hole, never the user's intent); keep failed layers mounted so retries continue, and un-shed after N consecutive successful tile loads, re-applying terrain only if terrain was not the culprit.
- Stamp every build into the status line (`VIEW [shorthash]`): a user screenshot then proves which bytes their browser ran and ends stale-build confusion without asking for console logs.

## Staged DEM pipeline — Terrarium primary, budgets, cache, and HMR bus
When a real DEM must paint in the browser without blocking first paint, stage it Terrarium PNG primary → SRTM GL1 fine fallback → Copernicus last (no browser CORS):
- Terrarium (`s3.amazonaws.com/elevation-tiles-prod/terrarium/{z}/{x}/{y}.png`, CORS `*`, maxzoom 15, ~20 m effective at Fort McMurray via NRCan CDEM) is center-out, concurrency-capped (6), deadline-cut, and stitched with `stitchTerrariumGrid` — cap coarse stages with `maxTiles:16` so a 44 km window at z12 does not try to fetch 81 tiles (9×9) for first paint; fine center refines with `terr-f15` etc. Missed tiles stay no-data so SRTM layers show through via `_layeredSampler`.
- Keep one `globalBudgetMs` racing the whole pipeline (best-available stage wins on expiry, never a throw) plus per-stage budgets (`terrBudget`, `coarseBudget`); emit `getDemStatus`/`onDemStatus` per stage for HUD.
- Pin the status bus to `globalThis.__safepipeDem` — Vite dev serves `dem.js?t=<hmr>` so a bare `import('/src/ops3d/dem.js')` forks the module and the probe reads `idle` for the full 60 s while the twin's copy loads; one shared bus fixes it.
- IndexedDB cache is a warm-path optimization, not a gate: parallel `_cacheRead` calls that each `indexedDB.open('safepipe-dem')` can block on upgrade and cost 16 s in Playwright cold profiles, eating the whole global budget before Terrarium starts — use a singleton `_dbPromise` raced against a 900 ms timeout that resolves to `null` (fall back to network), and never `db.close()` a shared connection per-read.
- Cold first swap into the live DEM takes ~45 s (coarse ~31 s → live ~46 s → fine ~56 s; warm revisits ~3 s via cache): any check taken earlier sees the procedural fallback (round kettle lakes instead of irregular basins). Do not judge terrain fidelity — or diagnose 'the terrain data is wrong' — before the swap-in line lands; a user's screenshot may simply predate the swap.
