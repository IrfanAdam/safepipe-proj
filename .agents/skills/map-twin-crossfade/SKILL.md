# Map ↔ Twin Crossfade Hardening

## When to Use

Any view blending a MapLibre satellite/terrain base with a transparent
three.js overlay twin under one slider — especially for Safari/real-GPU
browsers where headless screenshots pass but hardware fails.

Rules learned from Safari black-tab wars (software GL passes, real GPUs fail):

- **Black hole rule**: a transparent overlay canvas over a dead/hidden map reads as black. Never strand the user there — when one side dies, force mix toward the live side and say so in a sticky status line. Stronger form: keep the satellite ground on at EVERY mix and pitch (slider fades overlay emphasis only, never hides the base) — a 'pure twin' takeover mode is a black hole waiting for a tile failure. Restoring a takeover without giving the twin an opaque inside-disc ground reintroduces the exact black hole just removed — pair the two or do neither. And when a blend 'never arrives' at an end, read live opacities/visibility at both stops before theorizing: a slider that only scales overlay emphasis with a pinned-opaque canvas and force-visible ground cannot reach pure-twin by construction, which is a spec decision (true endpoints vs overlay-strength), not a timing bug.
- **Clip in world space, not overlay space**: a twin-perspective mask misregisters ~30px against the MapLibre mercator camera at oblique pitch, leaking square tile corners. Put the clip on the map side (terrain-conformant fill with circular hole) where alignment holds by construction.
- **Dual-host Esri gap-through**: Esri tiles have two keyless hosts for the same service (`server.arcgisonline.com` primary + `services.arcgisonline.com` backup). Mount both as separate raster sources/layers with the backup UNDER the primary at opacity 1 — failed primary tiles are transparent, so the backup shows through the gaps with zero runtime swap logic and survives Safari content-blocker kills on one host.
- **World-shell mask kills photo past lens**: an outer polygon of the whole mercator world `[-180,-85]→[180,-85]→[180,85]→[-180,85]` with a `circleRing(R, 72)` hole at the site radius creates one hard-edged band (photo full inside R, opaque page-bg fill outside). It must be the topmost fill layer so labels clip too, and its single edge at exactly R is shared with the twin-side hard clip — both sides agree with no stepped feather. A fixed-degree box outer leaks at zoomed-out oblique pitch where Mercator still shows imagery outside the box.
- **Split Terrarium source IDs**: MapLibre warns if hillshade shares the terrain source ID. Create two separate `raster-dem` sources from the same Terrarium URL (`TERRAIN_SOURCE_ID='terrain'` + `HILL_SOURCE_ID='terrain-hill'` — Ring-2 uses `terrarium`/`terrarium-hill`) — one for `setTerrain` exaggeration, one for the hillshade layer. A shared ID renders headless but loses hillshade when terrain is toggled and triggers a console warning; the split mirrors `src/ring2/mapbase.js:34-35` and `src/ops3d/sat-base.js:68-69` parity.
- **Keep site constant on port**: when copying a mask or dual-host pattern between variants (Sangachal 40.20N vs Fort McMurray 57.03N), re-derive `circleRing`/`lensCirclePts` from the target's `SITE`/`SANGACHAL` — verbatim copy places the disc on the wrong continent and still passes local tests.
- **Release pre-map guards**: any mix floor applied while the map is unmounted must be re-applied after mount lands, or the slider lies forever.
- **Twin owns the camera at every mix**: never make the map directly draggable at the pure-map end — the twin→map `jumpTo` sync must push authoritatively on EVERY twin frame, not only when the twin pose moved: an early-return-on-still-twin lets any map-side nudge (stray gesture, remnant zoom) persist until the twin next moves, which reads as permanent decoupling. Either re-push unconditionally or read back map center/zoom/bearing/pitch and snap on any disagreement beyond tolerance. When satellite mode feels frozen, the bug is dead orbit input (twin canvas set `pointer-events:none` below an effective-mix threshold), not missing map controls. Keep the twin canvas — or an input-catcher forwarding to the same OrbitControls — pointer-interactive at mix 0 so drag/zoom orbits the twin camera identically at all stops, with the map following via the existing sync.
- **Render exactly the pose you sync**: the twin must paint the same eye+target the map `jumpTo` receives, or the two view rays shear further apart with every pan at oblique pitch. OrbitControls' default `screenSpacePanning=true` lifts/drops `controls.target.y` on vertical screen drags while a terrain-snapped pose reporter claims a different height — set `screenSpacePanning=false` so pan stays in the ground plane, and snap `controls.target.y` to the DEM height after `controls.update()` but before the pose read and both paints (per-frame delta is slope × damped step, a fixed point at rest, so orbit feel is unchanged).
- **Stamps end stale-build confusion**: print a short build id in every status/caption line so one screenshot proves which code ran. Read the stamp in the user's evidence FIRST, before any new debugging — a stale cached page is the most common false 'you haven't fixed it', and no code change can reach a browser that hasn't loaded it. For `.mov` evidence, extract spread frames first (`ffmpeg -vf fps=2` to scratch, vision-read 3 across the clip) — gesture bugs live in the middle frames, not the endpoints. When the stamp proves stale, stop coding and give the refresh procedure: Safari caches dev pages aggressively, so Develop → Empty Caches (or `⌘⌥E`) then reload, or open a Private window for a guaranteed-fresh fetch — then confirm the new stamp before any further diagnosis.
- **Prove with fault injection**: abort/hang each tile host via request routing and require mount + frames; hang (not fail) is the killer — never gate mount on `load`, resolve hasty with timeout and engage terrain best-effort.
- **Verify on temp ports only** (never the user's dev ports); kill servers after and confirm ports free. When the user reports a blank satellite on their dev server (`:5175`), curl both the dev port and the temp port for `BUILD_ID` (`curl -s http://127.0.0.1:5175/src/ring2/main.js | grep BUILD_ID` vs `curl -s http://127.0.0.1:5198/src/ring2/main.js | grep BUILD_ID`) — a mismatch proves stale cache before any tile/mask debugging; also `curl -s http://127.0.0.1:5175/ops3d-ring2.html | grep ring2-dev` confirms the harness is served.
- **Measure dual-projection offset before theorizing**: project the same world ring points through both cameras (three `Vector3.project(camera)` vs `map.project(lngLat)`) and diff in px — rim divergence in the tens of px at oblique pitch proves a leak is misregistration, not a dead layer.
- **Unify perspective fov before chasing registration**: the twin camera fov must equal MapLibre's internal fov (`0.6435 rad ≈ 36.87°` — verify against the installed version's transform source, never memory). Identical center/zoom/bearing/pitch with different fov agrees at nadir and drifts with tilt (measured 60-vs-36.87: 5.8px nadir, 42px at 30°, 232px at 60°). Set the twin fov to the map's true fov, wire the live canvas height into the zoom law instead of a default constant, clamp twin tilt to the map's maxPitch, and prove with projection-parity asserts at pitch 0/30/60.
- **Key water to the water body's datum, then respect the DEM's clamp**: endorheic seas sit below MSL (Caspian −28m) — keying water to `sampleH < 0` pushed the shoreline ~7.4km inland. But never retarget the datum blindly: near-shore bathymetry can be clamped to a fill value (−27) that a `< −28` key erases entirely, deleting the sea. Pick the threshold between the fill and dry land, export it as one shared constant for every water/sea-color path, and pin both sides with tests.
- **Isolate layers by toggle + pixel-diff**: hide the suspect layer, screenshot, and diff against baseline — a large diff proves the layer is alive and the artifact comes from the other side; kills theory loops.
- **Judge blackness only on compositor screenshots after `dem:live`**: headless WebGL canvas readback (`drawImage`/`getImageData` off the live canvas) returns zeros under `preserveDrawingBuffer:false` even when the screenshot shows full imagery — a zero-pixel probe is a false failure, so gate pixel-truth on the PNG itself (a black disc compresses tiny, detailed satellite doesn't) plus vision. A mid-tile-load capture also reads black — wait for `tiles:16/16` before any verdict and re-run the stop after warm-up.
- **Read live render state, not stored UI state**: when a slider 'does nothing', evaluate actual material opacities/flags in the page — a guard can hold effective state away from the stored value with no visible error.
- **Shed without stranding**: on tile-error shed keep (never remove) the sat layers so retries continue, always reclaim the twin even when the user explicitly chose the dead side, and self-heal after N consecutive tile successes — re-applying terrain only if terrain was not the culprit.
- **Suspect deliberate gates before failures**: when the user says an angle or state 'worked before in one of the implementations', search git history for intentional behavior-change commits on that path (tilt gates, takeover modes, shed logic) before building failure theories — a regression from a design decision needs a retire, not a workaround. When retiring such a gate, update the tests asserting the old behavior in the same commit, or the suite reds on the intended change.
- **Diff the working variant before theorizing**: when one map variant renders in a browser where its sibling stays black, line-diff the two mount paths structurally before building failure theories — mount-once vs remount churn, which tabs have a show-triggered resize kick, module worker vs CDN bundle, terrain maxzoom, camera sync gates. The table of structural differences names the suspect (the lane only the broken variant walks); a shared-code theory wastes the round.
- **Gate construction on a non-zero container**: never construct a MapLibre map into a zero-size container — a canvas born 0×0 inside a `display:none` iframe keeps a zero backing store on real Safari that `resize()` never reallocates, and no remount ladder fixes a birth defect. Defer `new Map()` until `clientWidth>0` (IntersectionObserver + size check, 'waiting for viewport' status meanwhile); keep the resize/remount ladder only as fallback for instances that wedge after a healthy birth.
- **Map 0×0 resize fix — Safari retina canvas stuck blank**: when `status` shows `map:0x0 twin:2388x1202` and the slider shows nothing (black land + blue sea, no photo), the MapLibre canvas was 0 at mount and never resized — the twin Three.js canvas self-corrects via its own `onResize`, the map does not. After `mountMapBase` resolves, kick `map.resize()` on double-`rAF` + `400ms` + `1200ms`, observe the container with `ResizeObserver`, and keep a `window resize` listener for the map's lifetime — this collapses the 0×0 to the live viewport (2388×1202 on retina) with no reload. Verify at retina with `deviceScaleFactor:2` (`viewport 1194×601 → 2388×1202`) and at `mix:0/50/100` that `map:WxH` equals `twin:WxH` and stays non-zero. When `resize()` against a sized container still leaves the canvas zero across every tick, the instance itself is wedged — count consecutive failed ticks and after ~5s `map.remove()` + fresh `mountMapBase` into the live container, then re-adopt the mix/terrain guards; cap at 2 remounts. Past the cap, suspect the DIV itself — one that lived through `display:none` can hold a stale layout object in Safari so no remount into it will ever size — and swap it once (`replaceWith` a fresh same-id/class/style div, then mount there). While zero, print container dims AND recovery counters in the status (`map:0x0(c:1194x595)` + `STUCK0 rs:N rm:N newdiv:0/1 rserr:<msg>`) so one screenshot separates layout collapse (container 0) from wedged instance (container sized) and shows exactly which escalation stage ran; capture `resize()` errors into the counters instead of swallowing them — a throwing resize and a no-op resize need different next steps. Keep the recovery callable from module scope — a healer referenced across a closure boundary throws `ReferenceError` inside the best-effort `try/catch` and dies silently; bridge it explicitly and exercise the bridge headless. Free the old GL context (`WEBGL_lose_context`) before constructing the replacement — `remove()` alone leaves it alive until GC and three live contexts (twin + old + new) tip small GPUs into context loss on the new map; prune the dead instance's errors on adopt so the bar doesn't cry MAPERR over a healthy map; guard the remount entry against re-entry and re-check container size inside it (a hidden-again TOCTOU burns a remount).
- **Context loss bricks the canvas past all recovery**: if the GPU drops the WebGL context under pressure, MapLibre v6 locks its max canvas size to `[0,0]` and forces pixel ratio 0 — from there `resize()`, remount, and even a fresh container all stay 0×0 forever, which reads exactly like a wedged instance but no ladder step fixes it. Handle `webglcontextlost`/`webglcontextrestored` on map and twin canvases and answer a restore with a FULL clean re-mount (never a resize); stop burning a new GL context per remount (reuse-or-clean discipline) so the ladder itself can't push a small GPU over the edge; print live context count + loss events + pixel ratio in the status counters so one screenshot proves or rules out the brick (`pr:0` beside a loss event is the diagnosis). Ship the telemetry in the SAME commit as the fix it diagnoses, with a token decode guide in the commit report — a follow-up telemetry commit costs a full build/verify round-trip and leaves the first fix unverifiable on-device. Scope loss/telemetry flags to instance generations, not globals — a global lost-flag survives the remount and cries CTXLOST over the healthy replacement.
- **Hug the photo plane — meter-scale drape budget**: twin overlays float above the satellite photo by their lift heights, and at oblique pitch the parallax separates them visibly (contours hovering over dark ground, terrain edge vs photo edge). Keep every overlay lift inside a single small budget (single-digit meters, ordered ground < water < lines < ring < rim < mask) so worst-case oblique parallax stays subpixel and top-down stays pixel-identical. Never use a flat water plane — a constant-height plane stands tens of meters off the real DEM surface over water-adjacent relief; drape water per-vertex on the same DEM samples as the ground. Single-source the rim fade start with the overlay clip so both sides agree.
- **Prefer geometry over injected GLSL for clips**: a ring with a real hole (`THREE.RingGeometry`, draped to terrain per-vertex) renders identically to a plane + `onBeforeCompile` fragment-`discard` in headless chromium/webkit with zero custom shader code in the path — injected GLSL is a dependency on every GPU vendor's compiler (Metal-backed Safari compiles variants headless SwiftShader never exercises), geometry is not. Same drape density (~3 km cells), same render order/depth flags; edge crispness comes free from tessellation, no feather code needed.
- **Strip vendor-default chrome the design didn't ask for**: MapLibre's `NavigationControl`/`TerrainControl` read as a mystery zoom menu against sibling views that never had them — add only `ScaleControl` unless the spec names the rest.
- **Pin mercator + set sky for oblique**: an unset projection lets oblique pitch read the satellite as a convex planet limb; pin `mercator` and set a dark sky/fog that melts the horizon into the page background so tilt reads as terrain, not a sphere edge.
- **Conform the lens to the foreshortened disc at oblique**: a bounding-box circle clip (r = max span / 2) is far larger than the projected ellipse off-nadir, so the clip goes invisible and the base reads full-bleed. Project the world ring through the live camera keeping x/y spans separate (`{rx, ry}`), emit an `ellipse()` clip plus an ellipse gradient mask, and keep the old circular call shape working so top-down behavior and existing tests are untouched.
- **Debounce per-tick overlay hide (anti-flicker)**: a lens reconciled every frame must not snap off on a single gated tick — level heuristics mid camera flight and transient projection misses toggle show/hide visibly. Hold the last good geometry on a miss and require several consecutive misses before clearing; deliberate syncs (drill-in, toggle) bypass the debounce and hide immediately.
- **Gallery iframe lazy-mount hides Ring-2**: `gallery.html` renders Ring-2 as `<iframe data-src="./ops3d-ring2.html">` with no `src` while `[data-panel="ops3d-ring2"]` is `hidden`; `maybeMountRing2()` only sets `src` on tab click / hashchange. A blank gallery frame is an unmounted iframe, not a satellite failure. Headless repro must hit `/ops3d-ring2.html` directly on a temp port (never the hidden gallery panel), and when the user says "dont see it in ring 2" first ask them to click the Ring-2 tab or open the direct URL and read the `RING-2 [BUILD_ID]` stamp before debugging tiles or masks.
- **Real-Safari lane — stop theorizing, drive the user's actual Safari**: when headless passes but real Safari fails, safaridriver closes the gap. User enables Safari → Settings → Developer → 'Allow remote automation' + 'Allow JavaScript from Apple Events', then QUITS and reopens Safari (the toggles only bind on a fresh launch; `sudo safaridriver --enable` can exit 0 yet session-create stays denied on Safari 26 — the Settings checkbox + relaunch is what works). Then `safaridriver -p <port>` + `POST /session {browserName: safari}` yields a real-GPU session: navigate, execute JS (`window.__ring2.setMix`, canvases, the six-token status bar), screenshots — the full stop matrix driven programmatically.
- **Occluded-window trap**: a fully occluded automation window throttles rAF — the frames counter sticks and captures go stale (identical PNG sizes across different states) or near-black (tiny ~77KB PNG). Never trust a capture without a frame-delta across the step; front the window (osascript activate; `set index of window <title> to 1`) before evidence runs, and treat the user's own visible-window screenshots as the authoritative pixels.
