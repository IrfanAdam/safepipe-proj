### Why it fails today (so the fix is targeted)

Current terrain (read `src/ops3d/terrain.js:1-200`, `gridfloor.js`, `scene.js`, image attachment):

- **Relief too gentle:** `VEX 3.5`, total relief ≈ −40…+75 m over 40 km = average slope < 2 m/km. Contours are sparse, index rings barely close, flats swallow the geography.
- **Palette too quiet:** `BASE_COL #6a7377` / `INDEX_COL #9aa3a6` at `opacity 0.62/1.0` additive on `#0b0c0c` = grey-on-grey. Reference uses **white-on-black with hill wash to near-white** — the hilltops bloom.
- **Density wrong:** `LEVELS=20` power `1.5` → only 4 index rings. Reference has ~30+ fine rings with every 5th emphasised. Flats stay noisy because `SLOPE_MIN=0.0012` is too low.
- **Missing geography furniture:** summit pills `0.6` units above surface are tiny, interval/dem/datum not stated, drainage is a thin blue centreline with no V-kink enforcement, checker parterre absent (reference has diagonal diamond underlay), grid floor is red but unmodulated and not terrain-draped enough to read as volume.
- **Camera/fog hide relief:** fog `70–220` + plan dist `68` + `pitch 89` flattens everything. Reference is shot low-oblique (20–30°), with vignette+grain, so contours stack in depth.

The nested fix addresses each bullet in one lane each, so failure is local and visible.

### Reference deconstruction (what makes the sample work)

The attached sample (glowing topo on black) reads because:

1. **Closed rings on every high:** each hill is a bullseye of ~8 nested contours that tighten to a bright disk. You instantly know "two highs NW + SE, connected saddle".
2. **Luminance = elevation:** high ground is near-white; low ground is transparent black. The glow itself is the height cue — no hill-shade needed.
3. **Two-tone contour weight:** hairline base rings at ~0.4 opacity + heavier index rings at ~0.9, so you can count at speed.
4. **Clean flats, tight slopes:** flat basins have almost no rings; steep flanks have dense packing. Density encodes slope.
5. **Quiet graticule underlay:** a faint diamond checker (diagonal grid) gives scale without competing with contours — the red index grid in safepipe is the equivalent, but must be subordinate.
6. **No body mesh:** there is no opaque land slab. Contours + grid float on the void — depth is stacking, not shading.

Every task below reproduces one of these 6 properties with a numeric target.

export function field(x, z){
  const dip = -0.0018 * x; // 1.8 m/km eastward — slightly steeper for east/west cue
  const lakeMask = lakeWet(x,z);
  const swell = (0.035*Math.sin(x*0.16+1.2)*Math.cos(z*0.13-0.6)
               + 0.018*Math.sin(x*0.31-0.4)*Math.sin(z*0.27+2.0)) * (1-0.82*lakeMask);

**Step 1: Choose implementation — inline shader diamond is fool-proof**

Create `src/ops3d/checker.js`:

```js
import * as THREE from 'three';
import { field } from './terrain.js';
const R_MAP=20, VEX=3.2, Y=-0.06;
export function buildChecker(scene){
  const geo=new THREE.PlaneGeometry(44,44,44,44); // 1 km subdiv
  // displace vertices to drape + compute uv
  const pos=geo.attributes.position;
  for(let i=0;i<pos.count;i++){ const x=pos.getX(i), z= -pos.getY(i); pos.setXYZ(i,x, field(x,z)*VEX+Y, z); }
  pos.needsUpdate=true; geo.computeVertexNormals();
  const mat=new THREE.ShaderMaterial({
    uniforms:{ uR:{value:R_MAP}, uOpacity:{value:0.18} },
    vertexShader:`varying vec2 vP; void main(){ vP=vec2(position.x,position.z); gl_Position=projectionMatrix*modelViewMatrix*vec4(position,1.0); }`,
    fragmentShader:`
      varying vec2 vP;
      uniform float uR; uniform float uOpacity;
      void main(){
        float d=length(vP);
        float rim=smoothstep(12.0,19.5,d); // periphery fade
        // diamond checker: 2 km pitch diagonal
        vec2 q=vP*0.5; // 2 km
        float a=step(0.0, sin(q.x+q.y)*sin(q.x-q.y)); // 0/1 diamond
        float checker=mix(0.06,0.14,a); // subtle 8% contrast — not the 40% in reference
        float alpha=(1.0-rim)*checker*uOpacity;
        gl_FragColor=vec4(vec3(0.58,0.64,0.68)*alpha, alpha);
        // WebGL1-safe: no discard, just alpha
      }`,
    transparent:true, depthWrite:false, blending:THREE.AdditiveBlending, fog:false
  });
  const mesh=new THREE.Mesh(geo,mat); mesh.name='ops-checker'; mesh.renderOrder=0;
  scene.add(mesh);
  return { mesh, setSize(){}, update(t){ mat.uniforms.uOpacity.value=0.14+0.03*Math.sin(t*0.4); }, dispose(){ scene.remove(mesh); geo.dispose(); mat.dispose(); } };
}
```

Fallback if shader rejected: skip file, instead emit a `LineSegments` diamond grid (diagonal lines every 2 km, `opacity 0.12`, additive). Both are acceptable — shader is preferred for the reference's filled diamonds.

### Risks / tradeoffs

- **32 levels + 160 grid = ~3× more segments than 20×128.** Mitigated: `Line2` strips are cheap (vertex-count, not draw calls), chaining collapses segments to ~32 draw calls (one per level). Budget check: `geo.stats` must stay < 90k vertices. If over, drop to `N=144` — quality holds.
- **White neon vs health amber/red collision.** Mitigated: palette strictly bone/blue/grey + additive white; amber `#ff8c39` / red `#e31919` remain the only warm hues — at a glance, warm = health, white = terrain.
- **Shader checker on Safari WebGL1.** Mitigated: shader uses only `varying vec2`, `uniform float`, `sin/step/smoothstep` — GLSL1. If it fails, fallback is diagonal `LineSegments` at same pitch/opacity.
- **VEX change breaks pipe drape.** `network.js` drapes buried runs via `field(x,z)*VEX+0.03` — must import the single `VEX` constant from `terrain.js`, never duplicate. Task 2 makes `VEX` an exported const and adds a cross-module assert `VEX === gridfloor.VEX`.

### Open questions (answer before Task 2 if you want)

- Real DEM later: keep procedural field as fallback behind a `terrainSource: 'procedural'|'dem'` switch? Recommend yes — DEM plugs into `field(x,z)` sampler, contour engine unchanged.
